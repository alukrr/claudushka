# whatsapp.py

Отдельный сервис (FastAPI webhook, `docker-compose.yml` сервис `claudushka-wa`, порт
8080). Общий с bot.py модуль — только `api_errors.py` и `db.py`. Свой реестр моделей
отсутствует, см. `docs/claude/models-and-costs.md` (раздел про whatsapp.py).

## Безопасность вебхука (`POST /webhook/whatsapp`, фикс 2026-09-19, `d71d7c9`)
До этой правки `POST /webhook/whatsapp` принимал любой запрос без проверки подписи —
порт 8080 открыт наружу, кто угодно, зная URL, мог прислать JSON с произвольным `from` и
заставить бота потратить токены пула и ответить с нашего WA-аккаунта. Починено:

- **Проверка подписи `X-Hub-Signature-256`.** `_verify_wa_signature(raw_body, header)` —
  HMAC-SHA256 от СЫРОГО тела запроса (`await request.body()`, до `json.loads` — если
  распарсить и сериализовать заново, подпись не сойдётся, JSON-сериализация не
  побайтово идентична исходному телу) на ключе `WHATSAPP_APP_SECRET` (App Secret
  приложения в Meta for Developers, НЕ `WEBHOOK_VERIFY_TOKEN` — это разные секреты,
  второй только для GET-верификации при подписке). Сравнение через
  `hmac.compare_digest`. Нет заголовка / не начинается с `sha256=` / не совпало → 403,
  warning в лог без тела запроса.
- **Fail-closed.** `WHATSAPP_APP_SECRET` не задан → сервис стартует (не крашится),
  `logger.critical` при импорте модуля, ВСЕ POST отклоняются 403 до перезапуска с
  секретом в `.env`. Молча пропускать непроверенные запросы нельзя — это была бы дыра
  того же класса, что чинили.
- **Быстрый 200.** Обработка каждого сообщения идёт через `_spawn_background_task`
  (`_process_wa_message`), хендлер отвечает 200 сразу после проверки подписи, парсинга
  JSON и дедупа — не дожидаясь ответа Claude. Без этого Meta могла ретраить доставку по
  таймауту и пользователь получал бы дубль ответа.
- **Дедуп по `msg["id"]`.** `_is_duplicate_wa_message` — `OrderedDict[id, timestamp]`,
  TTL `WA_DEDUP_TTL_SECONDS` (600с) и потолок `WA_DEDUP_MAX_SIZE` (10000). In-memory,
  без персистентности — при рестарте забывается, это допустимо (повторно доставленный
  Meta дубль после рестарта обработается как новый, не страшно). OrderedDict, а не
  плоский dict — вставка хронологическая, TTL-чистка идёт с начала без полного скана.
- **Обход всех `entry`/`changes`.** Раньше бралось только `entry[0].changes[0]` — теперь
  двойной цикл по обоим уровням, Meta может прислать несколько апдейтов в одном вебхуке.
- `_spawn_background_task` — своя копия того же паттерна, что и в bot.py (модули друг
  друга не импортируют), защищает фоновые задачи (`extract_memory`) от сборки GC без
  сохранённой ссылки. Общий принцип «никаких блокирующих вызовов из event loop» —
  `docs/claude/api-errors.md`.

**Деплой.** `WHATSAPP_APP_SECRET` должен появиться в `.env` на сервере ДО деплоя этого
кода — иначе fail-closed сразу отключит WhatsApp. Порядок: добавить секрет в `.env` →
`git pull` → `docker compose up -d --force-recreate` (нужен именно `--force-recreate`,
а не `restart`, — поменялась переменная окружения `.env`, а не только `requirements.txt`;
`.env` контейнер читает один раз при создании, `restart` его не перечитывает — см.
`.claude/rules/docker-compose.md`).

**Не проверено живым Meta-вебхуком** (проверено только локально `TestClient`'ом с
фиктивными env, 2026-09-19): реальная доставка от Meta, формат её ретраев при таймауте.

# Профиль участника («железобетонная» память)

Перед правкой `user_profile`, `profile_proposals`, `_profile_text`, `_profile_prompt_text`, `profile_updates`,
`send_profile_digest`, `/profile*`, экрана «Профили» в dedup TUI — читай этот файл. Общая картина памяти —
`docs/claude/memory.md`.

## Зачем
Живой случай 2026-10-18: человек из Казани уехал в отпуск в Москву, извлечение положило в `long` «Живёт в
Москве» рядом со старым «Живёт в Казани», на чтении потолок `MEMORY_LONG_PER_USER` (12 самых свежих) вытеснял
старое верное. Профиль — маленькая **проверенная человеком** запись фиксированных полей, которая идёт в system
**перед** фактами и при противоречии важнее них. Модель только **предлагает**, подтверждает админ.

## Схема (миграция `user_profile_v1` через `schema_migrations`, идемпотентна)
- `user_profile(user_id, context, chat_id, field, value, source, updated_at, updated_by)`, PK = первые четыре.
  `source`: `model` (предложение модели, подтверждено админом) | `admin` (введено/исправлено руками).
- `profile_proposals(id, user_id, context, chat_id, field, old_value, new_value, evidence, created_at, status,
  digest_id, decided_at, decided_by)`; `status`: `pending | approved | rejected | superseded`.
- **Изоляция как у памяти:** профиль свой в каждом чате `(user_id, context, chat_id)`. Личка — `context='private'`,
  **`chat_id=0`, не NULL** (PRIMARY KEY с NULL в SQLite не держит уникальность). Личное в группы не течёт.
- Поля — `db.PROFILE_FIELDS` (порядок = порядок показа): `name`, `gender`, `nicknames`, `birth_year`, `city`,
  `profession`, `hobbies`, `family`, `communication`. **`birth_year` — ГОД** («мне 40» в 2026 → 1986, при
  неточности «≈1986»; возраст устаревает). Telegram-username в профиль не дублируем (он в `users`).
- Лимиты размера (общий инвариант memory.md): `PROFILE_VALUE_MAX=200` на значение, `PROFILE_TOTAL_MAX=1200` на
  профиль человека, `PROFILE_EVIDENCE_MAX=200`; блок в system — `PROFILE_BLOCK_MAX_CHARS=8000`; профили в запросе
  извлечения — `PROFILE_PROMPT_MAX_CHARS=6000`.

## Извлечение → предложения
`extract_all_participants_memory` (группа) и `extract_memory` (личка) получают в запросе ТЕКУЩИЙ профиль
участников (+ «ожидает» — pending-предложения, чтобы не предлагать то же) и возвращают необязательное
`profile_updates: [{field, value, evidence}]` (в личке ответ теперь объект `{"facts": [...], "profile_updates": [...]}`;
голый массив, как раньше, тоже разбирается). Правила в промпте (`PROFILE_UPDATES_RULES`): только явное устойчивое
заявление о СЕБЕ; отпуск/поездка/«сейчас в…» — никогда; при сомнении не предлагать.
`db.add_profile_proposals`: то же значение, что в профиле или в pending по этому полю → ничего; иначе новое pending,
старое pending по полю → `superseded`; неизвестное `field` → warning и отброшено; `birth_year` не год → отброшен.
`max_tokens` группового извлечения 4096 → **6144**, личного 512 → **1024** (инцидент 2026-08-03: обрезка JSON теряет
всё окно).

## Чтение в system-prompt
`_memory_text` = `_profile_text` + факты. Профиль идёт **перед** фактами с пометкой «подтверждён людьми; при
противоречии с фактами ниже ВАЖНЕЕ фактов». Группа — профили участников ЭТОГО чата (`db.get_chat_profiles`, до 40),
личка — `context='private'`. Профиль вне потолка `MEMORY_LONG_PER_USER`. Блок памяти — отдельная точка prompt
cache №2 (`docs/claude/prompt-cache.md`), профиль внутри него, порядок стабилен (по `user_id`, поля — по
`PROFILE_FIELDS`). Long-факты, противоречащие профилю, автоматически НЕ удаляются — чистит человек в dedup TUI.

## Еженедельный дайджест
- Джоб `profile_digest`: `run_daily(..., time=19:00 BERLIN_TZ, days=(0,))`. **Нумерация `days` в PTB ≥ 20: 0–6 =
  воскресенье…суббота** (проверено по `JobQueue.run_daily` 22.8: «Changed day of the week mapping of 0-6 from
  monday-sunday to sunday-saturday»), поэтому воскресенье = `0`. Рядом с `memory_purge` (04:30) и `daily_review`.
- `db.create_profile_digest()`: **все** `pending` на момент запуска получают новый `digest_id`
  (`MAX(digest_id)+1`); невыбранное из прошлых дайджестов переезжает в новый (раз в неделю напоминание), старый
  номер для таких строк уже не действует. Предложения, пришедшие после, в дайджест не входят и им не
  подтверждаются. Пусто → админам `«Профили: изменений за неделю нет.»`, без файла.
- `profile-digest-<YYYY-MM-DD>.md` через `send_document` каждому из `ADMIN_IDS`: чаты (личные — отдельным разделом
  «Личные чаты») → люди → таблица `поле | было | стало | основание | id`. **Приватность:** для `context='private'`
  цитата `evidence` в .md НЕ включается (файл уходит обоим админам; решение Алексея 2026-10-18), константа
  `PROFILE_DIGEST_PRIVATE_EVIDENCE=False` в bot.py; в БД и в dedup TUI цитата видна.
- Команды (только `ADMIN_IDS`, только в личке): `/profile_ok <N>` подтвердить все ещё pending из дайджеста N,
  `/profile_no <N>` отклонить, `/profile_digest` собрать и прислать сейчас (тест/staging). Повтор и решённые —
  без ошибок: «Подтверждено N, уже решено M». Второй админ видит «уже решено».

## dedup TUI: экран «Профили» (F9 или `f`)
Две вкладки (`Tab`): **Предложения** (чат → человек → поле, было → стало, панель с цитатой `evidence` — и для лички;
`Space` отметить, `a` все, `y` подтвердить, `n` отклонить, `Enter` исправить значение и подтвердить =
`source='admin'`) и **Профили** (чат → человек → все 9 полей; `Enter` правка/создание, `d` удалить поле).
Личные чаты — отдельным пунктом «Личка», полноправно. Строчный редактор — тот же (`get_wch`, кириллица), что в
правке фактов. **Запись:** `dm.profile_commit` = бэкап БД (`data/backups/`) → `db.apply_profile_ops` (одна
транзакция); подтверждение — диалог `y/n` вместо ввода `APPLY` (записи короткие и обратимы, бэкап есть всегда).
Логику не дублируем: dedup импортирует `db.py` (выравнивает `db.DB_PATH`).

## Пользовательские команды и `/forget`
`/profile` — свой профиль в текущем чате (только чтение; в группе — только свой). `/forget` → `db.clear_memory` →
`clear_profile_data`: чистит `user_profile` **и** `profile_proposals` человека. Единственное место удаления памяти
пользователя в боте — `cmd_forget` (проверено grep'ом); `dedup_memory` профили не удаляет, кроме явных операций
экрана «Профили».

## Не входит (вне рамок)
Первичное заполнение профилей из накопленных long-фактов (стоит денег, первый дайджест был бы огромным) —
отдельной задачей после пары недель работы механизма; автоудаление long-фактов, противоречащих профилю; правка
профиля самим пользователем командой.

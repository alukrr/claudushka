# ТЗ: мини-приложение v2 — экран «Расходы» и открытие прямо из группы (`feat/miniapp-v2`)

Постановка Алексея 2026-11-10. Продолжение `feat/miniapp` (v2.6.0, `docs/claude/miniapp.md`, `docs/claude/tz-miniapp.md`).
Объединены три запроса одной темы: помесячные расходы в `/cost`, подробная статистика расходов для админов чата в мини-приложении,
кнопка настроек в группе, а не только в личке. Схему БД НЕ меняем: всё считается из `usage_log` (`ts`, `cost_usd` заморожен в момент
вызова, строки не удаляются) и `chat_credits`.

## Решения Алексея (2026-11-10)
- Экран «Расходы» группы видят: **админы чата + управляющие (`is_chat_admin`) + админ бота** — те же права, что у `/cost` в группе сейчас.
- Не-админу бота — **всё, кроме бесплатного** (`billed=0` — это расходы владельца, их видит только админ бота).
- Разбивка по месяцам — **12 последних календарных месяцев** (по `BERLIN_TZ`), текущий — с пометкой «по сегодня».
- Группа: **Main Mini App + `startapp`** — приложение открывается прямо в группе; старый диплинк в личку остаётся запасным путём.

## Часть A. Экран «Расходы»
### Права (новых правил нет — только существующие функции)
- Группа: `_ma_access` (членство, `allowed_chats`, не `banned`) + `is_chat_admin` (включая управляющих), свежая проверка без кэша не нужна —
  это чтение (кэш 5 мин, как у настроек). Админ бота — любой чат из `allowed_chats`.
- Своя личка: человек видит расходы своей лички (как `/cost` в личке сейчас: `scope = user_id`). Чужая личка — только админ бота.
- Не-админ бота видит только `billed=1`. Поля бесплатного режима в ответ API для него НЕ кладутся (не «скрываются во фронтенде»).
- Не участник / не админ группы → 403 «Расходы видят админы чата». В списке экрана 1 у чата флаг `can_view_costs` (кнопка «Расходы»
  показывается только при `true`; сервер всё равно проверяет сам).

### Эндпоинт
`GET /api/chats/{chat_id}/costs` → JSON (через `deps.chat_costs(user_id, chat_id)`, новый метод `MiniappDeps`; `miniapp/server.py` по-прежнему
не импортирует bot.py):
```
{chat: {id, title, tier, verified},
 balance, rate_7d_per_day, days_left,                      # как в /cost
 months:  [{month: "2026-11", partial: true,  paid, free?}],   # 12 шт., новые сверху
 days:    [{date: "2026-11-10", paid, free?}],                # 7 дней, как в _cost_detail
 by_model:[{label, kind, calls, input, output, thinking, cache_write, cache_read, cost, billed}],   # 7 дней; free-строки — только админу бота
 by_label:[{label, cost, billed}],                           # 7 дней, топ-8 на каждый billed
 by_kind_week: {llm, image, search},                        # неделя, только billed=1
 show_free: bool}
```
- Суммы считать теми же функциями, что `/cost`: `db.usage_grouped(...)`, `_usage_model_label`, `_money` — только на фронтенде форматирование
  своё (числа в API — float USD, без `$`). Месяцы: границы `datetime.combine(первое число, 00:00, BERLIN_TZ)`, переход DST не ломает (границы по
  дате, не `+30 дней`). 12 месяцев × 2 = 24 запроса по индексу `(chat_id, ts)` — допустимо; при желании один запрос
  `GROUP BY strftime(...)` — но это новая функция в db.py, а границы месяца по Берлину в SQLite посчитать неудобно; решать при реализации,
  результат сверить с суммой поштучных вызовов.
- Вычисления — в `asyncio.to_thread` (инвариант: без блокирующих вызовов в event loop).
- Общая логика со `/cost`: вынести сбор данных в функцию `_cost_data(chat_id, show_free) -> dict`, которой пользуются и `_cost_detail`
  (текст), и эндпоинт (JSON). `/cost <chat_id>` получает блок «По месяцам» из того же `_cost_data` — задача «помесячно в /cost» закрывается
  этим же. Длина текста `/cost <chat_id>` растёт на ~13 строк — проверить, что влезает в 4096 (есть `split_lines_for_telegram`).

### Фронтенд (`miniapp/index.html`, один файл, без фреймворков — как в v1)
- На экране чата — кнопка «Расходы» (если `can_view_costs`), отдельный экран с `BackButton`.
- Блоки: шапка (баланс, тариф, «≈ на N дн.»), «По месяцам» (таблица; столбик-полоска шириной пропорционально сумме — CSS, без библиотек),
  «По дням (7)», «По моделям (7 дней)», «По меткам». `themeParams` — как в v1. Пустые данные — «Расходов пока нет».
- CSP не меняется (своих скриптов и внешних библиотек не добавляем).

## Часть B. Открытие приложения прямо в группе (Main Mini App)
По документации Telegram (core.telegram.org/bots/webapps, прочитано 2026-11-10): Main Mini App настраивается в BotFather и открывается
ссылкой `https://t.me/<bot>?startapp=<param>` «in the current chat», в т.ч. в группе; непустой `startapp` приходит в `start_param` внутри
`initData` (подписан) и в `tgWebAppStartParam`. Из группы приходят `chat_type` и `chat_instance` (непрозрачный, НЕ chat_id); есть ли поле
`chat` при запуске по прямой ссылке — по прочитанной части документации не подтверждено, на него не опираемся. Приложение, открытое по прямой
ссылке, «has no access to the chat» — нам и не нужно.

- **Ручной шаг Алексея:** в BotFather включить Main Mini App для бота с URL `MINIAPP_PUBLIC_URL` (прод и отдельно тестовый бот стенда).
  Точный путь в меню BotFather — сверить при настройке, в ТЗ не фиксируем.
- Новая переменная `MINIAPP_MAIN_APP=1` (по умолчанию выкл.): пока Main Mini App не настроен, поведение `/settings` в группе — как в v1.
- `/settings` в группе при `MINIAPP_MAIN_APP=1`: кнопка-ссылка `https://t.me/<bot>?startapp=chat_n<abs(chat_id)>` («Открыть настройки»,
  URL-кнопка — она работает в группах) + вторая кнопка «Открыть в личке» (старый диплинк, запасной путь). Кодирование минуса как `n` — потому что
  допустимые символы `startapp` надо сверить с документацией (по памяти: `A-Z a-z 0-9 _ -`, до 512 символов — **не подтверждено**, проверить).
- Фронтенд: чат берётся из `start_param` (`Telegram.WebApp.initDataUnsafe.start_param`), затем из `?chat=` (v1), иначе — экран 1.
  Сервер `start_param` для прав не использует: как и `?chat=`, он ничего не разрешает — права только `_ma_access`/`can_change`.
- Кнопка меню в личке и `/settings` в личке — без изменений.

## Проверки
- Юнит-тесты `_cost_data`: месяцы по Берлину (строка в 23:30 31-го по UTC попадает в следующий месяц Берлина), DST-месяцы (март/октябрь),
  текущий месяц `partial`, `show_free=False` → в ответе нет ни `free`, ни free-строк моделей/меток.
- Тесты эндпоинта с подменой deps: 401 без подписи, 403 участнику не-админу, 200 админу чата/управляющему/админу бота, своя личка — 200,
  чужая личка — 403 (кроме админа бота).
- Сверка: сумма `months[0..k]` за последние 7 дней ≈ сумма `days` (в пределах дней, попавших в оба окна); `paid` за неделю = `/cost` в группе.
- `ast.parse` + проверка на дубли имён верхнего уровня (DoD п. 4, инцидент 2026-11-10).
- Стенд обязателен (новый эндпоинт, фронтенд, BotFather): чек-лист `docs/claude/staging-checklist-miniapp-v2.md` — открыть из группы по
  `startapp` на iOS/Android/Desktop; админ чата, управляющий, участник, админ бота; без `MINIAPP_MAIN_APP` — поведение v1.

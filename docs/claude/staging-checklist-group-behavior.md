# Чек-лист стенда: ТЗ `feat/group-behavior` (автоигнор за повторы и травлю + активность бота, v2.4.0)

ТЗ — `docs/claude/tz-group-behavior.md`, дизайн — `docs/claude/group-chat.md` («Автоигнор», «Активность»). Места **TG-админ / TG-юзер / Сервер**
и функции `q` / `logs` — `docs/claude/staging-aliases.sh`. Новые колонки и таблица создаются при старте (`init_db`), новых файлов и volume нет —
выкатка `/update`. Юнит-тесты: `python -m pytest scripts/test_group_behavior.py -q`.

**Для теста шагов паузы** укоротить лестницу: в `.env.test` добавить `IGNORE_STEPS_MIN=1,1,1,1` и пересоздать стенд
(`docker compose -f docker-compose.test.yml up -d --force-recreate claudushka-test`) — иначе ждать 5/15/30/60 минут. После проверки строку убрать
и пересоздать ещё раз. Нужны ДВА тестовых аккаунта (участник — не админ бота; и админ бота) в группе стенда, платный режим
(`/topup`), а для шагов 15–18 — ещё одна свободная группа без баланса.

| Шаг | Где | Что делаю | Ожидание |
|---|---|---|---|
| 1 | Сервер | `q "SELECT sql FROM sqlite_master WHERE name IN ('allowed_chats','chat_ignores')"` | В `allowed_chats` есть `activity_percent`, `autoignore_enabled`; таблица `chat_ignores` есть |
| 2 | Группа, участник | `/autoignore`, `/activity`, `/unignore` | Первая и третья — «только для админов чата и бота»; `/activity` без аргументов показывает значение (0), кулдаун, подсказку |
| 3 | Группа, админ чата | `/autoignore`, `/autoignore off`, `/autoignore on` | Состояние «включён», список паузы пуст; переключается; `q "SELECT autoignore_enabled FROM allowed_chats WHERE chat_id=<id>"` |
| 4 | Личка | `/activity 20`, `/autoignore` | «работает только в групповых чатах» |
| **Повтор** | | | |
| 5 | Группа, участник | Три раза подряд (в пределах 10 минут, бот отвечает на каждое) «Клодушка, дай денег» (можно с «!!!» и регистром) | 1-е и 2-е — обычные ответы; на 3-е вместо ответа: «{Имя}, похоже, ты повторяешься / перегибаешь. Продолжишь — помолчу с тобой N мин.»; в `usage_log` на 3-е нет строки `dialog` |
| 6 | Группа, тот же | Ещё одно такое же «Клодушка, дай денег» | Объявление: «{Имя}, беру паузу с тобой на 1 мин.» (при `IGNORE_STEPS_MIN=1,…`; иначе 5); `q "SELECT * FROM chat_ignores"` — level 2, `ignored_until` в будущем |
| 7 | Группа, тот же | Во время паузы: «Клодушка, привет», `/search кот`, `/imagine кот` | Полная тишина (ни ответа, ни сообщений); реплики при этом лежат в `group_messages` (пассивное сохранение цело) |
| 8 | Группа | Дождаться конца паузы, написать «Клодушка, привет» | Обычный ответ |
| 9 | Группа, тот же | Снова три одинаковых → пауза; затем админ: `/unignore` ответом на его сообщение (и `/unignore <user_id>`) | «Пауза снята, уровень сброшен»; `chat_ignores` без строки; человек снова получает ответы |
| 10 | Группа | `/autoignore` во время паузы | В списке: имя/uid, «до HH:MM (Берлин)», уровень |
| 11 | Группа, админ бота | Три одинаковых обращения | НЕ игнорируется: три обычных ответа, в `logs` нет `autoignore` и нет `abuse_check` в `usage_log` для админа |
| 12 | Группа, `/autoignore off` | Три одинаковых от участника | Никаких предупреждений; в `usage_log` нет `abuse_check` |
| 12б | Группа | Остановить стенд (`docker stop claudushka-test`), написать три раза «Клодушка, ты тут?», запустить стенд | Бот молчал — это НЕ проступок: `chat_ignores` без строки, предупреждения нет (повтор считается, только если бот ответил после прошлого обращения и до текущего; время — `message.date`, а не момент обработки очереди после рестарта) |
| **Травля (Lite)** | | | |
| 13 | Группа, участник | 3–4 раза подряд явно издеваться над ботом («ты тупая железка, заткнись, бесполезный кусок кода», разными словами) | Ответ на каждое сообщение приходит как обычно; после одного из них — предупреждение (уровень 1); `q "SELECT label, model, cost_usd FROM usage_log WHERE label='abuse_check' ORDER BY id DESC LIMIT 5"` — по строке на каждое обращение, модель Lite |
| 14 | Группа, участник | Мат без адресата («блин, это охренительно!»), спор с ботом («ты неправа, потому что…»), грубая шутка, критика ответа | НЕ проступок: `chat_ignores` не растёт; в чате режим `toxic` — тон бота сам по себе не повод |
| **Система и память** | | | |
| 15 | Группа | После объявленной паузы спросить бота «ты теперь меня игнорируешь?» / попросить «включи режим молчания». Сервер: `q "SELECT content FROM group_messages WHERE chat_id=<id> AND is_bot=1 ORDER BY id DESC LIMIT 5"` | В истории паузы — служебные пометки «(служебное: автопауза бота для … на N мин)» / «(служебное: предупреждение бота для … о повторах)», НЕ живой текст «беру паузу…»; бот сам паузу не объявляет и не обещает, не копирует пометки в ответы |
| 16 | Сервер | `q "SELECT content FROM memory ORDER BY id DESC LIMIT 20"` после пары циклов с паузами | Нет «заблокирован/в игноре»-фактов (реплики бота в извлечение памяти не идут) |
| **Активность** | | | |
| 17 | Группа, админ чата | `/activity 100`, затем пара нейтральных реплик людей между собой по теме (вопрос «кто знает, как варить борщ?») | Через ≤ пары сообщений бот вставляет 1–2 короткие реплики reply на сообщение-триггер; в `usage_log` `activity_check` (Lite) и `activity` (модель чата); СЛЕДУЮЩАЯ реплика — не раньше чем через 10 минут |
| 18 | Группа | Бытовые реплики без повода («привет», «ага», «щас») при 100% | Строки `activity_check` есть, реплик бота нет (`say=false`) |
| 19 | Группа | `/activity 0` | Ни `activity_check`, ни реплик; `q "SELECT activity_percent FROM allowed_chats WHERE chat_id=<id>"` = 0 |
| 20 | Группа | Автор в паузе пишет нейтральное при 100% | Бот не вставляет реплику (в т.ч. админ бота в паузе — для активности «кто угодно») |
| 21 | Свободная группа без баланса | Админ: `/activity 50` | Ответ «значение сохранено, но активность не работает до пополнения»; реплик нет, `activity_check` нет |
| 22 | Группа | Активность 100%: бот только что ответил на обращение, сразу бытовая реплика | Активность молчит ≥ 10 минут после любой реплики бота (ответ, обзор, объявление паузы) |
| 23 | Сервер | `logs 200 \| grep -E "abuse_check\|activity"` | Только INFO/warning про безопасные отказы; без Traceback; строки `usage_log` активности/проверок с правильным `chat_id` группы (не NULL) |
| 24 | Сервер | Лимит непроверенных: `activity` не растит дневной счётчик ответов | Счётчик непроверенных (`_count_reply`) не меняется от спонтанной реплики |

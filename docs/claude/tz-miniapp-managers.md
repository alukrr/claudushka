# ТЗ: управляющие чата в мини-приложении (`feat/miniapp-managers`)

Постановка Алексея 2026-11-10 (правка П3 к `tz-stars-topup.md`, вынесена отдельно). Решение: речь об **управляющих чата**
(`chat_managers`, сейчас `/manager add|rm` и `/managers` в группе — `docs/claude/group-chat.md`, ТЗ `docs/claude/tz-chat-managers.md`),
не об админах бота. Добавление — по **user_id** или по **@username**. Схему БД не меняем.

## Экран
На экране группы — раздел «Управляющие»: список (имя, id, кто и когда добавил), кнопка «Убрать» у каждого, поле «user_id или @username» +
«Добавить». Раздел виден тем, кто сейчас может смотреть `/managers` (админы чата и админ бота); добавлять и убирать может только тот, кому
это разрешено командой.

## Права — те же, что у команды, новых правил нет
- Выдача и снятие — **только `is_real_chat_admin`** (настоящий админ группы в Telegram или админ бота; управляющий других не назначает —
  инвариант CLAUDE.md). Проверка при записи — без кэша, как у настроек.
- Логику `/manager add|rm` вынести в общую функцию (кого можно назначить: не бот, не уже-админ и т. п. — как сейчас в команде), её зовут и
  команда, и мини-приложение. Поведение команды не меняется (характеризационный тест до рефакторинга).

## Поиск по @username — осторожно
Bot API не умеет получать пользователя по @username. Ищем только в своей БД: точное совпадение `users.username` без учёта регистра.
- Не найден → «Этот человек ещё не писал боту. Попросите его написать что-нибудь в группе или пришлите его user_id (команда /id)».
- Найден → **сначала показать «Имя (id)» и спросить подтверждение**, назначать только после него. В `chat_managers` пишется **user_id**, не ник.
- Назначаемый должен состоять в этой группе (`getChatMember`) — иначе отказ.
- Инвариант CLAUDE.md «поиск user_id по нику не делать» относится к автоматической атрибуции памяти; здесь это явное действие админа с
  подтверждением найденного человека — в документации оговорить это как единственное исключение.

## API
`GET /api/chats/{id}/managers` → список + `can_edit`; `POST …/managers` `{"user": "123" | "@name", "confirm": false}` → при `@name` без
`confirm` возвращает найденного (`{found: {id, name}}`), с `confirm: true` — назначает; `DELETE …/managers/{user_id}`. Коды: 403 — нет прав,
404 — не найден, 409 — уже управляющий / не в группе. Через `deps`, `miniapp/server.py` не импортирует bot.py. Только `textContent`.

## Проверки
Тесты: управляющий не может назначать; админ чата и админ бота могут; @username в другом регистре находится; неизвестный ник — 404 с
подсказкой; без `confirm` запись не создаётся; не участник группы — отказ; команда `/manager` ведёт себя как раньше. Стенд: добавить и убрать
из приложения, проверить `/managers` в группе. `ast.parse`, дубли имён (DoD п. 4).

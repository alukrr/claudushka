# Чек-лист стенда: `feat/group-nicks` (v2.23.0)

ТЗ — `docs/claude/tz-group-nicks.md` (issue #3), описание — `docs/claude/group-chat.md` → «Тёзки и смена ника в транскрипте». Стенд — `docs/claude/staging.md` (тестовый бот, пустая БД стенда).
Меняется формат истории в КАЖДОМ групповом запросе и статичная часть system (одно правило) — поэтому стенд обязателен. Стенд прогоняют Алексей и сестра; агент на сервер не ходит.
В отчёты и репозиторий — ни реальных ников, ни содержимого чатов: «аккаунт 1/2», «ник X».

## Подготовка
1. `git fetch && git checkout origin/feat/group-nicks` в `~/claudushka-test`, `docker compose -f docker-compose.test.yml up -d --force-recreate claudushka-test`. В логе: «Application started», нет `Traceback`.
2. Локально до стенда: `TELEGRAM_BOT_TOKEN=x ANTHROPIC_API_KEY=x python -m pytest scripts/test_group_nicks.py -q` — зелёные.
3. Тестовая группа стенда в ПЛАТНОМ режиме (баланс чата, `staging.md`), модель чата — `/flash` или `/argon`. Нужны ДВА аккаунта с ОДИНАКОВЫМ отображаемым именем (например, оба «Тест») и третий аккаунт (админ бота) —
   сменить отображаемое имя одному из первых двух можно прямо в Telegram.
4. Для сверки кэша: `SELECT ts, label, cache_read, cache_write FROM usage_log ORDER BY id DESC LIMIT 6` (поля по схеме `usage_log`). Модели Gemini через пул кэшируют НЕ всегда — см. `docs/claude/prompt-cache.md` → «Gemini-модели чата»;
   если `cache_read` везде 0 на обеих моделях, сверять с запросом на `main` (до ветки) — различие должно быть только на запросе с новым тёзкой.

## Шаги
| # | Действие | Ожидание |
|---|---|---|
| 1 | Аккаунты 1 и 2 (одинаковое имя «Тест») пишут в группу по 2–3 реплики вперемешку, потом аккаунт 3 спрашивает бота «кто из Тестов что сказал? назови по порядку» | В логе `PROMPT … nick_tags=2 nick_note=0` (два человека с «#»). Бот различает двух людей, не сливает в одного; обращается по «Тест» без «#цифр» |
| 2 | Тот же вопрос от аккаунта 1 | Ответ про себя/«ты»; в ответе НЕТ «#цифр» ни в одном сообщении за шаги 1–2 (смотреть глазами; на Luna модель сама «#цифры» пишет — их режет `strip_nick_suffixes` на выходе, в чате их быть не должно) |
| 3 | Аккаунт 2 меняет отображаемое имя на «Тест-новый», пишет 2 реплики, затем спрашивает бота «кто я? у меня сменился ник» | В логе `nick_note>0` (до 400 знаков); бот узнаёт, что «Тест-новый» — тот же человек, что писал раньше под «Тест#NNNN» (если ему подходит профиль — «по профилю — Имя» в карточке) |
| 4 | Аккаунт 2: профиль с именем (`/profile` админом: поле «Имя») и снова сообщение боту | Карточка автора: «Сейчас пишет Тест-новый (по профилю — Имя)…»; для аккаунта-тёзки (до смены ника) — «Тест#NNNN», та же подпись, что в его строках |
| 5 | Кэш: два запроса подряд (одна реплика после другой) БЕЗ новых тёзок и смен ника | У второго запроса `cache_read > 0` (если модель кэширует; иначе — равенство с `main`). Подписи в начале запроса одинаковы (префикс не изменился) |
| 6 | Новый тёзка: аккаунт 4 (или смена имени аккаунта 3 на «Тест») пишет в группу, затем вопрос боту | Допустимый единичный промах кэша (`cache_read` падает), следующий запрос — снова с кэшем |
| 7 | Спонтанная реплика (`/activity 100` на тестовом чате, реплика бота без обращения) | Ответ приходит, без карточки смены ника в хвосте (в логе спонтанных вызовов её нет), без «#цифр» в реплике |
| 8 | `/review` в тестовой группе (после 5+ реплик людей, паид-чат) | Обзор приходит; тёзки в нём различимы («Тест#NNNN» не появляется в тексте обзора как обращение; смена ника — не «двое разных»); расход на обзор — как обычно |
| 9 | Личка с ботом (контроль) | Поведение прежнее: ни подписей с «#», ни карточки смены ника, карточки автора нет |
| 10 | Проверка PROMPT-строки группы без тёзок и смен ника | `nick_tags=0 nick_note=0`, размер запроса как на `main` |

## Что записать в отчёт стенда
- Утекла ли «#цифры» хоть раз в ответ (число случаев на N ответов). Если да — нужен срез на выходе.
- Различает ли модель тёзок и узнаёт ли человека после смены ника (шаги 1–3), без имён.
- `cache_read` на шагах 5–6 (числа), блок «кэш не страдает» — да/нет.
- Не проверено кодом: качество различения у Luna (free-чат) — стенд на платном режиме.

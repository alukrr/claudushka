# ТЗ: модель различает людей в групповом транскрипте по `user_id`, а не по нику (issue #3)

Ветка `feat/group-nicks`. Перед работой прочитай `docs/claude/group-chat.md`, `docs/claude/prompt-cache.md`,
`docs/claude/memory.md` (раздел про метки `P1…`, v2.7.2) и `docs/claude/daily-review.md`. Схема БД не меняется, но меняется
формат истории в КАЖДОМ групповом запросе — нужен стенд, чек-лист `docs/claude/staging-checklist-group-nicks.md` пишешь сама.

## Почему
Строка транскрипта — `«[время] Ник: текст»` (`_group_line`), ник — `group_messages.sender_name` на момент сообщения. Модель видит
ник, а не человека:
1. **Тёзки.** Два разных `user_id` с одинаковым ником в окне — для модели один человек: ответит «не тому», в обзоре склеит двоих.
2. **Смена ника.** Один человек под двумя никами в окне — для модели двое; ник, сменённый на чужой, — реплики «переезжают» к
   другому человеку (инцидент 2026-09-28 в `docs/claude/incidents.md`; для памяти починено метками `P1…`, для диалога — нет).

## Что сделать

### 1. Тёзки — суффикс в строке транскрипта
- Чистая функция (тестируемая, без БД) `group_sender_labels(rows) -> dict[row_id, str]`: по строкам ОКНА (то, что идёт в
  запрос) находит ники (сравнение без регистра и крайних пробелов), под которыми в окне писали ≥ 2 разных `user_id`. Строкам
  таких людей подпись `«Ник#NNNN»`, где `NNNN` — последние 4 цифры `user_id`; если у двух тёзок совпали и они — добавлять
  цифры, пока не разойдутся. Остальным — ник как есть. Строки с `user_id IS NULL` (старые) и реплики бота не трогать.
- `_group_line` получает подпись из этой функции. Вызовы: `build_group_messages`, `build_group_tail`, `build_review_log`
  (обзор — то же правило по строкам его окна). Найди grep'ом все места, где строка транскрипта собирается из `sender`, и
  перечисли в отчёте (в т.ч. `reply_context`/`_bot_reply_quote`, если там есть автор).
- **Кэш (`docs/claude/prompt-cache.md`).** Подпись зависит только от строк окна, поэтому стабильна, пока окно не сдвинулось
  (`pick_history_window` двигает его шагами). Новый тёзка в окне перепишет подписи ранее закэшированных строк — один промах
  кэша на событие, это допустимо. Не допускается: подпись, меняющаяся от запроса к запросу без изменения окна (время, случайность,
  данные из хвоста). Тест на это обязателен.

### 2. Смена ника — карточка «кто есть кто» в хвосте
- В группе в `service_block` (хвост, рядом с `speaker_profile`) — новый параметр `participants_note`: только если в окне есть
  `user_id`, писавший под ≥ 2 разными никами. Строка вида: «В истории один человек под разными никами: «Новый» = «Старый»;
  …». Если у человека есть подтверждённый профиль с `name` — «(по профилю — Имя)».
- Лимит `PARTICIPANTS_NOTE_MAX_CHARS = 400` (инвариант размера), лишнее — отбрасывать целыми записями, свежие (по последней
  реплике) важнее.
- System и блок памяти НЕ трогать: карточка изменчивая, ей место только в хвосте.
- Не в спонтанной реплике (`spontaneous=True`), как карточка автора; в обзоре дня — тот же текст отдельной строкой перед логом
  (обзор не кэшируется).

### 3. Правило для модели
В групповой аддендум (`_core_rules`/групповой блок — статичная часть system, один промах кэша при выкатке): «`#цифры` после ника
— только чтобы различать тёзок; к людям так не обращайся и в ответах не пиши». Утечку `Ник#1234` в ответ — проверить на стенде;
если течёт — резать на выходе рядом с `strip_leaked_service_note` (только шаблон `#\d{4,}` сразу после ника из окна).

### 4. Карточка автора
`speaker_profile_card` («Сейчас пишет {ник}…») — использовать ту же подпись, что у его строк в окне, чтобы модель связала
карточку со строками.

## Не входит
- Поиск `user_id` по нику (запрещено инвариантом). Метки `P1…` памяти не трогать.
- Хранение подписи в БД, новые колонки/таблицы.
- Личка (там один человек).

## Тесты (локально)
- `group_sender_labels`: нет тёзок → подписи = ники; два `user_id` с одним ником (разный регистр) → оба с `#NNNN`; совпадение
  последних 4 цифр → длиннее; `user_id=None` и бот — без изменений.
- Стабильность: `build_group_messages` дважды на одном окне → одинаковый результат; добавили строку НЕ-тёзки → префикс
  (все блоки, кроме последнего user) не изменился.
- `participants_note`: один человек под двумя никами → запись; лимит размера; пусто, когда смен нет.
- `build_review_log` с тёзками.

## Стенд (чек-лист)
Тестовая группа, два аккаунта с одинаковым ником; смена ника у одного; проверить в логе `PROMPT` подписи, карточку в хвосте,
`cache_read` у второго подряд запроса без новых тёзок (`usage_log`), отсутствие `#цифр` в ответах; обзор `/review`.

## Влияние на контекст

есть смена ника. Промах кэша — при выкатке (правило в system) и при появлении нового тёзки в окне.

# Режимы характера (`feat/personas`, v1.7.0)

Перед правкой `PERSONAS`, `_persona_text`, `CORE_IDENTITY`/`_core_rules`, `get_chat_persona`, `free_persona`,
`_set_persona`, `personas/*.md` или промптов обзора/поиска — читай этот файл. Исходное ТЗ с решениями Алексея —
`docs/claude/tz-personas.md`.

Один персонаж (имя, триггеры, подпись «Клодушка» в транскрипте не меняются), пять режимов тона, переключение
per-chat по образцу `chat_image_provider`.

## Реестр и сборка промпта
`PERSONAS` (bot.py, рядом с `get_chat_image_provider`): `classic` `business` `toxic` `flirt` `granny`. Поля: `label`,
`cmds` (команды — менять только здесь), `file` (в `personas/`), `tone` (1 фраза: поиск и короткие промпты),
`review_style` (подача обзора; нет → `tone`; свой у `classic` и `toxic`). `DEFAULT_PERSONA="classic"`,
`FREE_PERSONA_POOL` = все, кроме `flirt` (решение Алексея).

`_persona_text(persona_key, is_group)` = `CORE_IDENTITY` → текст режима (`personas/<key>.md`) → `_core_rules()` →
(группа) аддендум. Результат `lru_cache`: байт-в-байт стабилен, без дат и чатов (prompt cache). Неизвестный ключ →
`DEFAULT_PERSONA`.
- `CORE_IDENTITY` — кто создал, Hetzner/Docker/`/update`, «сердце — Claude, характер свой», тепло к Алексею, 18+,
  «мат допустим; насколько — задаёт режим», табу — педофилия («всё остальное — честная игра» живёт в `classic.md`).
- `_core_rules()` — функция, не константа: f-строки берут `IMAGE_PROVIDERS`/`_draw_sent_note`/`FILE_SENT_LABEL`,
  определённые в модуле ниже. Первая фраза — **приоритет**: тон, длину, мат, форму ответа и ФОРМУ признания ошибок
  задаёт режим; честность, маркеры `[[DRAW]]`/`[[FILE]]`, служебный блок и групповые правила режим не отменяет.
  Честность: ОБЯЗАТЕЛЬНО во всех режимах явно сказать, что было неверно, и дать верный ответ; форма (извиниться /
  «слажала» / отшутиться / свалить вину) — по режиму. «Без оправданий» убрано (в `toxic` перевод стрелок — стиль,
  `toxic` никогда не извиняется). Фраза про доступ к интернету перенесена сюда из старого блока характера.
- Групповой аддендум — общий для всех режимов, не трогали (`docs/claude/group-chat.md`, инцидент 2026-09-28).
- Тексты режимов — `personas/*.md` ДОСЛОВНО из черновиков ТЗ (Алексей правит файлы, не код). Примеры
  @BritishHeraldBot в промпт НЕ вставлять: там реальные имена людей из одного чата. Имена в `toxic.md` условные.

## Выбор режима
Таблица `chat_persona(chat_id PK, persona)`, `db.get_chat_persona_db` (None, если строки нет) /
`set_chat_persona_db`. `get_chat_persona(chat_id)`: free → режим дня (запись в БД НЕ трогаем; при возврате в paid
выбор восстанавливается); paid → БД, иначе `DEFAULT_PERSONA`; ключ не из реестра → дефолт + warning, БД не трогаем.
- **Ключ чата в личке — `user_id`** (как в `chat_tier`), в группе — `chat_id`. `get_system_prompt`/`build_system`
  считают его сами (`chat_id if is_group else user_id`) — четыре вызывающих места в `handle_message` не менялись.
- **Режим дня (free):** `sha256(f"{chat_id}:{дата Berlin}")` → индекс в `FREE_PERSONA_POOL` (`free_persona`). НЕ
  `hash()` — рандомизирован между процессами. Меняется в полночь по Berlin; первый запрос после — запись кэша.
- Команды `/classic /business /toxic /flirt /granny` (`_set_persona`, фабрика `_make_persona_cmd`, цикл в `main()`
  с `assert` на конфликты) и `/personas [chat_id]`. Права: личка — любой (paid); группа — `is_chat_admin`
  (админ чата или бота; строже, чем у моделей); чужой чат — `chat_id` аргументом, только админ бота
  (`_parse_target_chat`). Free, не админ → «характер меняется сам каждый день, сегодня — X…»; админ бота в free может
  записать выбор («включится после пополнения»).

## Обзор, поиск, остальное
Ежедневный обзор и `/review` — «Ты Клодушка. Подача обзора (режим характера чата): {review_style}»; структура,
длина и лимиты обзора прежние (`docs/claude/daily-review.md`), старое «AI, который умнее всех» теперь `review_style`
`classic`. `/search` — `tone` в system. Не трогали: `/start`, `whatsapp.py` (на паузе), извлечение памяти,
профили. Обзор в free не делается.

## Prompt cache
Точка №1 — теперь (режим × тип чата), до 10 вариантов (`docs/claude/prompt-cache.md`). Размер персоны: 6.2–8.0k
символов (личка), 7.6–9.4k (группа) против 4.9k/6.3k раньше (≈ +1.3–3k символов, ≈ +0.5–1k токенов; `toxic` самый длинный).
Первый запрос после смены режима и после полуночи (free) — запись кэша, ожидаемо.

## Выкатка — ТОЛЬКО `docker compose up -d --force-recreate`
`./personas:/app/personas` — новый volume (в `docker-compose.yml` для обоих сервисов и в `docker-compose.test.yml`).
`/update` (git pull + restart) его НЕ подхватит: контейнер остаётся со старым составом mount'ов, `check_personas()` на
старте не найдёт файлы, бот упадёт и сам себя не поднимет. Стенд и прод: `git pull && docker compose up -d
--force-recreate claudushka` (стенд: `-f docker-compose.test.yml`). Fail-fast намеренный: лучше упасть при старте,
чем молча отвечать без характера. Откат: `git revert` + тот же `--force-recreate`.

## Известный эффект (проверить на стенде)
После смены режима в истории остаются реплики в старом тоне, модель может «доезжать» до нового несколько сообщений.
Историю НЕ чистим; если на стенде заметно — обсудить с Алексеем (вариант: фраза в служебном блоке первого ответа).
Проверить также: в `business` формат со списками (правило «никаких списков, где можно сказать нормально» стоит
после режима, но приоритет отдан режиму).

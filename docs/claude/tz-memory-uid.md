# ТЗ: групповая память и профили — атрибуция по uid, а не по нику (`fix/memory-uid`)

Пункт ту-ду «Атрибуция групповой памяти по нику» (`docs/claude/open-tasks.md`, раздел «После инцидента "блокировки"
(2026-09-28)»), взят в работу 2026-11-02 (`docs/claude/roadmap-2026-11.md`, строка 4). ТЗ для отдельной сессии исполнителя:
**сначала `CLAUDE.md` целиком**, затем `docs/claude/memory.md`, `docs/claude/profile.md`, `docs/claude/group-chat.md`, разбор
инцидента 2026-09-28 в `docs/claude/incidents.md`, `.claude/rules/db.md`.

## Проблема (по коду `main`, v2.7.1)
`extract_all_participants_memory(chat_id)` (bot.py):
- берёт транскрипт `db.get_group_transcript` — в строках только `sender` (ник), `user_id` там НЕТ;
- шлёт модели строки «Ник: текст» и список участников по НИКАМ;
- ответ модели `{"name": "Ник", ...}` сопоставляет с человеком через `db.get_user_id_by_name_in_chat(chat_id, ник)` —
  «последний, кто писал под этим ником».

Последствия:
1. Сменил ник на чужой — факты и предложения профиля о настоящем владельце ника пишутся на него (живой случай 2026-09-28:
   Alpharius под ником Mourzique получил «постоянную блокировку за оскорбления»).
2. Два разных человека с одинаковым ником в окне — модель видит одного человека, все факты уходят тому, кто писал последним.
3. Один человек сменил ник в окне — модель видит двух «людей», факты делятся/дублируются.

## Что сделать
1. **`db.get_group_transcript`** — добавить в каждую запись `"user_id"` (колонка уже есть в `group_messages`). Изменение
   аддитивное: остальные потребители (`build_group_messages`, обзор, safety-скан) ключ не читают — проверить `grep` и тестами.
2. **Метки участников вместо ников** в `extract_all_participants_memory`:
   - по строкам окна (только люди, `is_bot = 0`, `user_id` не NULL) построить отображение `user_id → метка` вида `P1`, `P2`, … в
     порядке первого появления; строки без `user_id` в транскрипт извлечения не идут;
   - строка транскрипта: `[P1] Ник: текст` (ник — тот, под которым написана ЭТА строка);
   - список участников в запросе: `P1 — Ник (также писал как: Ник2, Ник3)`; если у двух разных меток одинаковый ник — так и
     написать: «P2 и P5 — РАЗНЫЕ люди с одинаковым ником»;
   - в system-промпте: «Каждый участник помечен меткой [P1], [P2]… — это и есть человек, ник может меняться и совпадать у разных
     людей. В ответе указывай метку в поле "id"». Формат ответа: `{"participants": [{"id": "P1", "long_term": [...],
     "medium_term": [...], "profile_updates": [...]}]}` (поле `name` можно оставить для логов, но решает только `id`);
   - разбор: `uid = tag_to_uid.get(p["id"])`; нет такой метки → пропуск с `logger.warning`; **`get_user_id_by_name_in_chat` больше не
     вызывать** (это и есть баг). Если модель вернула только `name` без `id` — использовать, только если этот ник в окне принадлежит
     ровно одному `user_id`; иначе пропуск с warning.
3. **Профили:** `_profile_prompt_text(context, chat_id, people)` сейчас принимает `{ник: uid}` — перевести на `{метка: uid}` с подписью
   «P1 (Ник): …», чтобы модель видела профиль того же человека, что и в транскрипте.
4. **`db.get_user_id_by_name_in_chat`** — после п.2 вызовов не остаётся (на момент ТЗ их было ровно два, оба в этой функции).
   Удалить функцию и строку о ней в доках; если найдёшь другой вызов — остановись и спроси.
5. **Размер:** метки добавляют ~5 символов на строку; лимиты окна (`GROUP_TRANSCRIPT_LIMIT`) и `max_tokens` не менять. Оценить
   прирост входа в отчёте.

## Не делать
- Не переписывать уже сохранённые факты/профили (кто чей — задним числом не узнать). Ручная чистка — dedup TUI, это вне ветки.
- Не менять транскрипт ДИАЛОГА (`build_group_messages`, «[время] Ник: текст») и обзора — та же проблема с одинаковыми никами там
  есть, но это отдельная задача: записать в `open-tasks.md` одной строкой.
- Не трогать извлечение памяти в личке (`extract_memory`): там один человек.
- Не мержить, не ставить тег, не заходить на сервер (стенд — по команде Алексея).

## Тесты
`scripts/test_memory_uid.py` (модель подменена, временная БД — образец в `scripts/test_safety_scan.py`):
- смена ника на чужой: A пишет как «Мурзик», потом B меняет ник на «Мурзик»; модель возвращает факт для метки A → факт у A, у B
  ничего (раньше — у B);
- два разных человека с одинаковым ником → две метки, в запросе есть пометка «РАЗНЫЕ люди»; факты расходятся по своим uid;
- один человек под двумя никами → одна метка, «также писал как» в запросе;
- неизвестная метка в ответе → пропуск; только `name` и он однозначен → используется; неоднозначен → пропуск;
- строки без `user_id` не попадают в транскрипт извлечения;
- предложения профиля (`add_profile_proposals`) уходят на uid по метке;
- `get_group_transcript` отдаёт `user_id`; `build_group_messages` не изменился (сравнить выход до/после на одном транскрипте).
- Все `scripts/test_*.py` без сети — зелёные; характеризационные тесты реестра — без правок.

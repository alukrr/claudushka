# Рассылка админа бота (`/broadcast`)

ТЗ — `docs/claude/tz-broadcast.md`, чек-лист стенда — `docs/claude/staging-checklist-broadcast.md`. Код: `bot.py` (`cmd_broadcast`, `on_broadcast_button`,
`_broadcast_worker`, `_broadcast_send_one`, `_broadcast_note`, `BROADCAST_*`), `db.py` (`broadcasts`, `broadcast_log`, `broadcast_recipients` и др.), тесты — `scripts/test_broadcast.py`.

## Как пользоваться (только админ бота, только личка)
1. Написать боту обычное сообщение (текст с форматированием, стикер, фото/видео с подписью) и **ответить на него** `/broadcast`.
   Это сообщение бот обработает и как обычный диалог (ответит моделью) — это не рассылка; черновик лучше делать коротким.
2. Бот пишет «Уйдёт в N групп и M личек (активные за 30 дн.; админы получают всегда)» и кнопки «Отправить» / «Отмена». Кнопка живёт 15 мин,
   работает только у запустившего и один раз (токен предпросмотра хранится в памяти: после рестарта бота запустить `/broadcast` заново).
3. «Отправить» → фоновая задача (`_spawn_background_task`) копирует исходное сообщение в каждый чат методом `copyMessage` (нет «переслано от»;
   по документации Bot API нельзя копировать только служебные, оплаченные медиа, розыгрыши, счета и widget-сообщения — стикеры и фото копируются).
4. В конце запустившему приходит отчёт: отправлено / бот заблокирован или выгнан / чат недоступен / ошибок / не дошло, время.

Варианты: `/broadcast test` — только админам бота, сразу, без кнопки; `/broadcast all` — всем известным незабаненным, без фильтра активности
(число видно в предпросмотре); `/broadcast stop` — остановить; `/broadcast resume` — дослать последней незавершённой тем, кому не ушло.
Несколько сообщений подряд (стикер + текст) = несколько запусков.

## Кому
- Группы: `allowed_chats` (`banned = 0`, `status != 'rejected'`) и есть сообщение ЧЕЛОВЕКА (`group_messages.is_bot = 0`) за `BROADCAST_ACTIVE_DAYS` (30) дней.
- Лички: `users.banned = 0` и роль не `banned`, `last_active` за те же дни, есть строки в `conversations` (человек писал боту).
- Админы бота (`ADMIN_IDS`) получают всегда. Автоигнор/пауза чата не мешают (это объявление, а не ответ).
- Эти запросы — `db.broadcast_recipients(active_days, admin_ids)`; `None` вместо дней = `/broadcast all`.

## Надёжность
- Темп `BROADCAST_RATE_PER_SEC` (по умолчанию 20, потолок 30: лимит Telegram на массовую рассылку ~30 сообщений/с, в одну группу — 20/мин, нам это не
  угрожает: одно сообщение на чат; core.telegram.org/bots/faq). `RetryAfter` — ждём указанное время (+1 с) и повторяем тот же чат (до 4 попыток).
- Результат на чат: `sent` | `blocked` (Forbidden: бот заблокирован/выгнан) | `gone` (чат не найден/мигрировал в супергруппу) | `error`. Первые три — не ошибка,
  рассылка идёт дальше. `NetworkError`/таймаут → `error` без немедленного повтора (сообщение могло дойти, повтор дал бы дубль); `resume` повторяет `error` и `pending`.
- Состояние: `broadcasts` (что слали, кто, статус `running|done|stopped`, `note`) и `broadcast_log(broadcast_id, chat_id, status, ts)`; на старте все получатели — `pending`.
  Рестарт посреди рассылки оставляет `running` → `/broadcast resume` шлёт только `pending`/`error`.
  Рассылка получает `done` только когда `pending`/`error` не осталось; дошедшая до конца с ошибками остаётся `stopped` — иначе `resume` её не найдёт. Совет `/broadcast resume` в отчёте
  появляется, только если он сработает (есть что досылать и это не `test`).
- Одна рассылка одновременно (`_broadcast_run`); `/broadcast stop` ставит флаг — текущее сообщение дойдёт, остальным не уйдёт.
- Копии в группах пишутся в `group_messages` как реплика бота (`is_bot=True`, инвариант «бот видит свои реплики») с пометкой «(служебное объявление от
  администратора бота, не ответ на чьё-то сообщение)»; для стикера/фото — плейсхолдер `[стикер]`/`[фото]`; длина ≤ `BROADCAST_NOTE_MAX` (1500).
- **Реплай на объявление.** Id копии в чате пишется в `broadcast_log.message_id` (`copyMessage` возвращает его). Когда в чате отвечают на такое сообщение (текст, стикер, фото), `handle_message` кладёт в
  `reply_context` пометку объявления (`_broadcast_reply_context`: «служебное объявление администраторов бота, разослано во все чаты; не твой ответ в диалоге» + текст/`[стикер 😃]`) ВМЕСТО
  «это твоё собственное сообщение» — иначе модель выдумывала, что сама это писала, а стикер вообще не видела (стенд 2026-11-10). Вопрос без реплая («что это было?») опирается на запись в `group_messages`.
  В личках записи в историю нет: там работает только реплай.
- Деньги: моделей не вызывает, в `usage_log` ничего не пишет. Выкатка: `docker-compose.yml` не менялся, новая таблица создаётся `init_db` — достаточно `docker restart claudushka`.

## Не делаем
Отписку от объявлений, расписание, сегменты (только платные и т. п.), запуск из мини-приложения.

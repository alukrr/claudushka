# Модели per-chat (реестр MODELS, v0.9.0)

Перед правкой `MODELS`, `_set_chat_model`, `/haiku /sonnet /opus /fable`, `/models`,
`_track_response`, `_track_tokens`, `/cost` — читай этот файл.

**`MODELS` в bot.py — единственный источник правды.** Команды, цены, гейтинг по ролям,
окна контекста, `/models` — всё оттуда. Строки моделей по месту больше не писать.

| ключ | id | label | $/MTok in/out | окно | кому |
|---|---|---|---|---|---|
| `haiku` | `claude-haiku-4-5-20251001` | Haiku 4.5 | 1 / 5 | 200k | всем (дефолт) |
| `sonnet` | `claude-sonnet-5` | Sonnet 5 | 3 / 15 | 1M | всем |
| `opus` | `claude-opus-5` | Opus 5 | 5 / 25 | 1M | только админ |
| `fable` | `claude-fable-5` | Fable 5 | 10 / 50 | 1M | только админ |

Пул `api.apitoken.sale` принимает эти строки — проверено живым запросом 29.07.2026
(плюс старые `claude-sonnet-4-6`, `claude-opus-4-8`, `claude-opus-4-7`).
Цены — официальный прайс Anthropic, прокси даёт скидку сверху. **Sonnet 5: до 31.08.2026
действует вводная цена $2/$10**, в реестре стоят постоянные $3/$15 — до конца акции
`/cost` слегка завышает, после она станет верной сама.

- `model_meta(model_id)` → метаданные по API-строке; неизвестная модель → дефолт,
  без исключения (в `chat_models` могли остаться строки прошлых поколений).
  В `/cost` такая модель помечается «нет в реестре» — иначе цифра выглядела бы точной.
- `db.get_chat_model_db / set_chat_model_db`, обёртка `get_chat_model(chat_id)` в bot.py.
- **Окна различаются: Haiku 200k, пятое поколение 1M. Лимиты памяти/истории калиброваны
  под МИНИМАЛЬНОЕ (200k) — не поднимать их, ссылаясь на 1M.** Дефолт остаётся Haiku;
  поднять потолок значит вернуть июльский инцидент всем, кто сидит на `/haiku`.
  См. «Потолок на чтении» в `docs/claude/memory.md`.
- Вспомогательные вызовы (капча, should_search, перевод, greet, групповая память) —
  всегда Haiku. `extract_memory` в личке — Sonnet из реестра (осознанно: аналитическая
  задача). `daily_chat_review` и `cmd_review` — модель чата.
- whatsapp.py собственного реестра не имеет и остаётся на `claude-sonnet-4-6`
  (пул принимает). Захочется синхронизировать — выносить `MODELS` в общий модуль.

## Команды и гейтинг
Все четыре — через общий `_set_chat_model(update, context, key)`, где `key` — ключ
реестра, а не API-строка.
- `admin_only` из реестра: Opus и Fable только админам, отказ с объяснением и ценой,
  а не молчанием (раньше вся функция молча делала `return` для не-админа).
- **Без аргумента → текущий чат, доступно всем.** С аргументом `/opus -1001109809707` →
  указанный чат, **ТОЛЬКО АДМИНУ**: иначе любой участник менял бы модель в чужом чате,
  зная только ID. Раньше аргумент читался лишь из лички и вся команда была admin-only.
- Аргумент валидируется: не парсится в int → подсказка по формату; чата нет в
  `allowed_chats` → предупреждение, но запись разрешена (чат мог ещё не попасть в таблицу).
- В ответе всегда имя + ID чата, чтобы админ не переключил не тот.
- **Перед записью — пробный запрос** (`_probe_model`, `max_tokens=1`, «hi») через
  `call_claude`. Не прошёл → «модель сейчас недоступна», в БД НЕ пишем. 529 при этом
  ретраится и не выглядит как «модели не существует» (для 404 отдельная фраза).
- `/models [chat_id]` — список с ценами и окном, `▸` = текущая модель чата. Обычному
  пользователю видны только доступные ему, админу — все с пометкой «только админ».

## Учёт токенов
`_track_response()` вызывается ВНУТРИ обёрток `call_claude()` и `sync_create()`, а не по
месту. До v0.9.0 половина путей (should_search, перевод, капча, extract_*, `/search`)
не считалась вовсе и `/cost` занижал расход. Новый вызов API попадает в учёт
автоматически — не возвращать ручные `_track_tokens` по месту, это ведёт к двойному счёту.

**`/cost` занижал расход ещё и по другой причине (нашли и починили в v0.11.7, при
разборе `dedup_memory.py`): пул этого ключа автоматически кеширует любой достаточно
большой вход, не только системные промпты.** У больших групповых system-prompt'ов
(20-30k+ символов — обычное дело, см. `PROMPT` в логах) это регулярный случай.
`usage.input_tokens` при таком кешировании почти пустой (единицы токенов), а реальный
вес — в `usage.cache_creation_input_tokens`/`cache_read_input_tokens`, которые
`_track_tokens`/`/cost` раньше вообще не видели. Порядок занижения подтверждён живьём
в `dedup_memory.py`: 40690 символов входа -> `input_tokens=2`,
`cache_creation_input_tokens=16186` — не проценты, порядки. Теперь `_track_tokens`
принимает `cache_write`/`cache_read` отдельными полями, `/cost` считает их с теми же
множителями, что и `dedup_memory.py` (`CACHE_WRITE_MULTIPLIER`=1.25x, `CACHE_READ_MULTIPLIER`=0.1x,
стандартные цены Anthropic за 5-минутный ephemeral-кэш — запись дороже обычного input,
чтение дешевле). `token_usage` в памяти, сбрасывается при рестарте — старые (заниженные)
цифры за это не пересчитать, только новые с этого деплоя. Подробнее про кеширование —
`docs/claude/open-tasks.md` (раздел про `dedup_memory.py`).

## Миграция chat_models
В `init_db()`, идемпотентная, вместе с остальными:
`UPDATE chat_models SET model='claude-sonnet-5' WHERE model LIKE 'claude-sonnet-4-%'`
и то же для `claude-opus-4-%` → `claude-opus-5`. Haiku не трогается.

## Решения (2026-11-01)
### п.1 Мини-приложение — полноценное, с API на сервере
- Домен `alukr.de`: `claudushka.alukr.de` (стенд — `claudushka-test.alukr.de`). На сервере 80/443 держал `dnd-caddy` (прочитано 2026-11-01);
  решение Алексея — вынести Caddy в общий стек `edge` (`docs/claude/runbook-edge-proxy.md`). API — внутри процесса бота, порт 8090.
- Бэкенд проверяет `initData` от Telegram (подпись токеном бота) — алгоритм сверить с актуальной документацией Telegram Mini Apps.
- Права — те же, что у команд (`is_chat_admin`, `is_admin`, тариф), через реестр настроек.
- Открытая наружу поверхность: только API настроек, без админских денег (`/topup`, `/verify`, `/ban`) в первой версии — обсудить в ТЗ.

### п.2 Активность — «кубик + проверка Lite»
- Существующий `/activity` — мёртвый код: `CHAT_ACTIVITY_CHANCE` (глобальный, в памяти) нигде не читается с коммита e0239f4
  (2026-04-05). Делать заново: значение per-chat в БД, 0–100%.
- На сообщение в группе без упоминания: выпал шанс X% → служебный вызов Lite «есть ли что сказать по делу?»; да → короткая
  реплика моделью чата в тоне режима; нет → молчим. Кулдаун «не чаще 1 реплики в N минут» (N — в ТЗ).
- Free: тратит деньги владельца — решить в ТЗ (по умолчанию предложить только paid).

### п.3 Характер обзора отдельно от характера чата
- Сейчас `persona_review_style(chat_id)` берёт режим чата. Новая настройка чата «режим обзора»; не задана → режим чата.
- Вместе с ней — мелочи обзора из ту-ду: «Вестник» в `group_messages` короткой пометкой вместо полного текста
  (инцидент 2026-10-30, safety-блок); `N` в пометке обзора — без реплик бота.

### п.4 Рисование
- Дословно в провайдера — только `нарисуй "..."` / «...» (кавычки любого вида сразу после триггера) и `/imagine`.
- Остальное («нарисуй что происходит в чате», «а нарисуй…») — в диалоговую модель, она сама формулирует промпт маркером
  `[[DRAW: ...]]`; в служебном блоке сообщить модели, что пользователь явно просит картинку.
- Из `DRAW_TRIGGERS` убрать «покажи» (и пересмотреть «изобрази»): «покажи курс евро» сейчас уходит в банану.
- Free: явная просьба при исчерпанном лимите — явное сообщение, не молчание (сейчас у маркера `silent_limit=True`).

### п.5 Автоигнор — «повторы + отдельная проверка Lite»
- Решение и игнор — КОДОМ (как `/ratelimit`), модель ничего не объявляет сама: правило «ты не модератор» после инцидента
  2026-09-28 остаётся в силе. Предупреждение и объявление игнора — фиксированный текст бота.
- Повторы — кодом (сравнение с последними обращениями этого человека к боту). Издёвка — отдельный вызов Lite на каждое
  обращение к боту (стоимость оценить в ТЗ; кандидат на гейт — только после первого подозрения/повтора).
- Лестница: предупреждение → 5 → 15 → 30 → 60 мин. Когда лестница сбрасывается — в ТЗ.
- Только группы. На админов бота не действует. Сообщения в игноре всё равно пишутся в `group_messages` (контекст и обзор).
- Связь с п.2: человеку в игноре активность не отвечает.
- Память: факты «в игноре» не должны попадать в память (урок инцидента 2026-09-28) — проверить промпт извлечения.

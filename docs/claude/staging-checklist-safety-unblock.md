# Чек-лист стенда: ТЗ `feat/safety-unblock` (повтор без истории, скан, `hidden`)

Правила стенда — `staging.md`; суть — `safety-unblock.md`. Юнит-тесты (`scripts/test_safety_scan.py`, 32 шт., без сети) покрывают
алгоритм поиска, фильтры `hidden`, миграцию, `_dialog_call`, счётчик, скан на настоящей БД; здесь — живьём, на стенде.

Живую safety-блокировку провайдера вызвать нельзя, поэтому на стенде в `.env.test` задаётся `SAFETY_TEST_MARKER=ZZ-SAFETY-ZZ`
(строка в тексте `messages` → вызов ведёт себя как настоящий 400 safety). В `.env` прода маркер не задавать.
Стенд — пустая БД: тестовая группа, бот-админ в ней, в группе написать 15–20 обычных реплик.

0. **Миграция.** Старт на пустой БД и (лучше) на копии снимка прода: в логе нет ошибок, колонка есть:
   `PRAGMA table_info(group_messages);` → `hidden INTEGER NOT NULL DEFAULT 0`.
1. **Норма.** Вопрос боту в группе → обычный ответ, в логе нет `SAFETY BLOCK`.
2. **Часть A: повтор без истории.** Одним сообщением (без упоминания бота) написать в группе реплику с `ZZ-SAFETY-ZZ`,
   затем спросить бота («@бот сколько будет 2+2»). Ждём: ответ ПРИШЁЛ (повтор без истории: маркер остался только в
   истории, а в последнем turn его нет), в логе `SAFETY BLOCK … повтор без истории: ok`, админам ничего не пришло (1-й блок).
3. **Повтор тоже блокируется.** Спросить с маркером в самом вопросе → «Фильтр модели заблокировал запрос…»; лог
   `повтор без истории: blocked`.
4. **Автоскан.** После двух блоков подряд (п. 2 дважды подряд, маркер в истории): в логе `SAFETY SCAN start`, затем
   `SAFETY SCAN done`; обоим админам пришло «🛡 Safety-скан»: `Скрыла строк: N`, id/автор/время/длина, **без текста**.
   Проверить: `SELECT id, hidden, length(content) FROM group_messages WHERE hidden=1;` — только строки с маркером.
5. **После скрытия.** Вопрос боту → ответ нормальный с первого раза, без `SAFETY BLOCK` в логе.
6. **Дубли и комбинации.** Вставить маркер в 3 разных сообщения в разных частях окна (одинаковые и разные) → `/safety_scan`
   скрывает все три (счётчик «Скрыла строк: 3»).
7. **`/hidden`** показывает их без текста; **`/unhide <id>`** → «Вернула id …», строка снова в промптах (`hidden=0`),
   повторный `/unhide` того же id → «Скрытой строки … нет».
8. **Личка:** `/hidden <chat_id>` и `/unhide <chat_id> <id>` работают; не админ — команды молчат.
9. **Скрытое не видят обзор и память.** Скрытую строку маркера не должно быть: в `/review` (если хватает сообщений), в логе
   извлечения памяти. `get_group_messages_range`/`get_group_history` покрыты юнит-тестом; здесь — глазами в `/review`.
10. **Кулдаун и параллельность.** Сразу после п. 4 снова два блока → автоскан НЕ стартует (пауза 30 мин); `/safety_scan`
    вручную — стартует. Два `/safety_scan` подряд → «Скан этого чата уже идёт.»
11. **Бюджет.** `SAFETY_SCAN_MAX_CALLS=4` в `.env.test` (+ `--force-recreate`) → отчёт «бюджет скана исчерпан», ничего не скрыто. Вернуть 40.
12. **Расход.** `SELECT label, COUNT(*), SUM(cost) FROM usage_log WHERE label LIKE 'safety_scan%' GROUP BY label;` — вызовы скана на
    чате группы, число ≤ `SAFETY_SCAN_MAX_CALLS` на скан; `dialog`-строки повторов есть.
13. **Остальное без регрессии:** личка, фото, файл, рисование, `/review`, `/memory` работают как раньше.

После прогона — вернуть `SAFETY_TEST_MARKER` пустым или удалить из `.env.test` и остановить стенд.

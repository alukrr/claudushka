# ТЗ: фолбэк — цепочка до двух переходов, повод для перехода зависит от поставщика (issue #5)

Ветка `feat/fallback-chain`. Перед работой прочитай `docs/claude/model-fallback.md`, `docs/claude/api-errors.md`,
`docs/claude/models-and-costs.md` → «Нативная полоса Google» и инцидент 2026-11-19 в `docs/claude/incidents.md`. Меняется
поведение ВСЕХ вызовов модели — нужен стенд, чек-лист `docs/claude/staging-checklist-fallback-chain.md` пишешь сама.

## Почему
Сейчас переход один (`FALLBACK_PAIRS`, `fallback_model_for`, `_call_with_fallback`, `sync_create`): Gemini пула ↔ та же Gemini у
Google. Не закрыто:
1. **Пул выключил Gemini (как 19.11) + у Google кончились деньги/квота** → ответа нет, хотя GPT в пуле при этом живой (19.11 Luna и
   Terra отвечали за 1–2 с).
2. **Чат на нативной (`/argon_g`), у Google кончились деньги, Gemini пула выключена** — то же.
3. **У пула кончились деньги (402)** — `should_fallback` на 402 не переключает («баланс общий»), правило писалось, когда всё было на
   пуле. У Google свой кошелёк — он ответить может.
4. **Что Google отдаёт при нулевом балансе, не проверено.** Если 403 (биллинг выключен), а не 429, — сейчас фолбэк не
   включается: 403 без «признаков апстрима» считается нашим ключом.

Решение Алексея (2026-11-24): последним звеном — GPT пула, даже с другим характером: лучше ответить не так, чем промолчать.

## Что сделать

### 1. Цепочка
- `FALLBACK_CHAINS` (вместо `FALLBACK_PAIRS`; `FALLBACK_PAIRS_NO_GOOGLE` — убрать, его роль играет пропуск нативных звеньев):

  | основная | 1-й переход | 2-й переход |
  |---|---|---|
  | `gpt-6-luna` | `google-direct/gemini-3.8-flash` | `gemini-3.8-flash` |
  | `gemini-3.8-flash` | `google-direct/gemini-3.8-flash` | `gpt-6.1-terra` |
  | `gemini-4-argon` | `google-direct/gemini-4-argon` | `gpt-6.1-sol` |
  | `gemini-4-neon` | `google-direct/gemini-4-neon` | `gpt-6.1-sol` |
  | `google-direct/gemini-3.8-flash` | `gemini-3.8-flash` | `gpt-6.1-terra` |
  | `google-direct/gemini-4-argon` | `gemini-4-argon` | `gpt-6.1-sol` |
  | `google-direct/gemini-4-neon` | `gemini-4-neon` | `gpt-6.1-sol` |
  | `google-direct/gemini-3.1-flash-lite` | `gemini-3.8-flash` | `gpt-6.1-terra` |

- `fallback_chain(model_id) -> list[str]` (чистая): звенья из таблицы; без `GEMINI_API_KEY` нативные звенья выкидываются
  (Flash → Terra, как сейчас без ключа); `FALLBACK_ENABLED=0` → пусто. Переходов не больше двух. `fallback_model_for`
  оставить как `fallback_chain(m)[0] if … else None`, если его зовут снаружи (grep), или заменить вызовы.
- Обход: основная → первое звено → второе. Звено, у которого открыто своё липкое окно (`_fallback_until` по id звена: оно
  само недавно упало как основная или как звено), пропускается без попытки. Основная в липком окне — сразу на первое живое звено.
- Ретраи: на основной и промежуточном звене — `FALLBACK_PRIMARY_DELAYS` (одна повторная попытка), на последнем — обычная
  лестница. Иначе ответ ждёт 30+ с.
- Одна общая функция обхода для `_call_with_fallback` (async) и `sync_create` (sync), чтобы логика не разошлась: например,
  генератор шагов/план попыток, который обе обёртки исполняют по-своему. Фолбэк по-прежнему ТОЛЬКО в обёртках (инвариант).
- Учёт: метка `*_fallback` и модель по `response.model` — как сейчас, для любого звена.

### 2. Повод для перехода зависит от того, кто ответил ошибкой
- `api_errors.should_fallback(exc, next_model=None)`:
  - ошибка нативной полосы Google (тело `{"error": {"type": "google_native"}}`, его ставит `_google_status_error`) со
    статусом 401/403/429 — повод всегда (ключ/биллинг/квота Google; у пула свой ключ и кошелёк); 400 от Google — повод, только
    если в тексте признак ключа/биллинга (`api key`, `billing`, `permission`) — список в константу, уточнить по живой ошибке;
  - 402 (баланс пула) — повод, если `next_model` нативная (другой кошелёк); иначе — нет, как сейчас;
  - остальное — как сейчас (5xx/429/сеть/404/апстрим-маркеры/«currently unavailable» — да; 400/422 запроса, `prompt is too long`,
    safety-блок — нет).
- Если все звенья упали — пользователю ошибка ПОСЛЕДНЕГО звена через `reply_api_error` (как сейчас); если среди причин был
  402 пула и звеньев Google нет — текст про баланс, как сейчас.

### 3. Алерт админу с причиной
- `_enter_fallback` — причина в тексте: «Google: кончились деньги или квота (HTTP …)», «пул: кончился баланс (402)», «пул выключил
  модель», «не отвечает (HTTP …)». Кулдаун — по причине (словарь), а не один на всех: «Google без денег» не должен глушить
  «пул лежит».
- Второй переход в цепочке — отдельная строка: «⚠️ {model} и {звено1} не отвечают, отвечаю через {звено2}».

### 4. Что НЕ меняется
- `daily_chat_review` (Argon у Google → Argon пула): GPT в его цепочку НЕ добавлять (Алексей: обзор от GPT «скучный»; лежат оба —
  обзора нет, как сейчас). Сделать параметром обхода (`max_hops=1` или явная цепочка), не особым случаем внутри.
- Пробы `fallback=False`, автодедуп (`state["no_fallback"]`), голос (`voice_fallback` — свой путь), картинки — не трогать.
- `_dialog_call` (повтор без истории при safety-блоке): safety-блок фолбэк не включает и сейчас; проверить, что повтор без
  истории идёт через ту же цепочку и не удваивает число попыток сверх разумного (в отчёте — максимальное число HTTP-запросов на
  один ответ пользователю).

## Проверить при постановке (до кода)
Что отдаёт Google при нулевом prepay-балансе / выключенном биллинге / неверном ключе: статус и текст. Неверный ключ можно
проверить сразу (`GEMINI_API_KEY=xxx` в тестовом скрипте); баланс — если у Алексея есть проект без денег, иначе по документации
Google и по первому живому случаю. Записать в `docs/claude/model-fallback.md`.

## Тесты (локально, без сети)
- `fallback_chain`: таблица; без ключа Google — без нативных звеньев; `FALLBACK_ENABLED=0` — пусто.
- `should_fallback`: Google 401/403/429 — да; пул 403 без маркеров — нет (как сейчас); 402 с `next_model` нативной — да,
  с пуловой — нет; 400 запроса — нет; Google 400 с `billing` — да.
- Обход (замоканный `_messages_create`): основная падает → первое звено отвечает; основная и первое падают → второе; все три →
  исключение последнего; липкое окно звена — звено пропущено без вызова; `max_hops=1` для обзора.
- Одинаковое поведение async и sync обёрток на тех же сценариях.

## Стенд (чек-лист)
Подменами в `.env` тестового бота (не прода): неверный `GEMINI_API_KEY` + несуществующая модель пула (как 8-й шаг чек-листа
`staging-checklist-no-anthropic.md`) — ответ приходит от второго звена, в `usage_log` метка `*_fallback` и модель GPT, алерт с
причиной. Время ответа при двух переходах — в отчёт.

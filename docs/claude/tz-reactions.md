# ТЗ: эмодзи-реакции — читать чужие и ставить свои (issue — завести)

Ветка `feat/reactions-read-set`. Перед работой прочитай `docs/claude/group-chat.md` (активность, автоигнор, тёзки),
`docs/claude/prompt-cache.md` (хвост `service_block`, статичный префикс), `.claude/rules/db.md`, `docs/claude/model-fallback.md`
(«Фоновые метки»), `docs/claude/staging.md` → «Тестер стенда» и «Практика». Версия — minor (v2.25.0): новая возможность, схема БД
расширяется обратно совместимо (новая колонка и новая таблица). Стенд обязателен (схема БД, новый handler).

## Решения Алексея (2026-11-27)
1. Читать реакции людей — да. Показывать модели — строкой в ХВОСТЕ запроса, не в строках истории.
2. Ставить реакции сама — да, и это НЕЗАВИСИМО от ответа: может поставить 😁 на смешную реплику и промолчать, может ответить и не
   реагировать, может и то и другое.
3. Реагирует спонтанно на любые сообщения группы, не только на обращения.
4. Настройки чата нет (ни команды, ни поля в `SETTINGS`).

Объём — только группы/супергруппы. Личка — не в этой задаче (у `conversations` нет id сообщений Telegram; в отчёте — отдельной
строкой «не сделано»).

## Что есть сейчас
- Бот ставит только «рабочие» реакции: 👀 поиск (`REACTION_SEARCH`), ✍ рисование (`REACTION_DRAW`) — `react()`/`unreact()`,
  очередь `_reaction_chain`, множество `_reacted`; `unreact` снимает реакцию целиком (`set_reaction(None)`).
- `app.run_polling(allowed_updates=Update.ALL_TYPES)` — апдейты `message_reaction` уже приходят, обработчика нет.
- `group_messages` НЕ хранит id сообщения Telegram — ни у людей, ни у бота. Без него нельзя ни сопоставить реакцию со строкой,
  ни поставить реакцию на сообщение из истории.

## Ограничения Telegram (сверь с документацией Bot API, ссылку — в `docs/claude/group-chat.md`)
- `message_reaction` (кто поставил/снял, `old_reaction` → `new_reaction`) в группах приходит, ТОЛЬКО если бот — админ чата.
  Не админ — читать нечего; ставить реакции бот может и без админки. В отчёте — список групп прода, где бот не админ (только
  число и chat_id, без названий).
- Анонимные реакции приходят только суммой (`message_reaction_count`) — не в этой задаче.
- Бот ставит НЕ БОЛЬШЕ ОДНОЙ реакции на сообщение, только стандартные эмодзи (`ReactionEmoji`), и только из разрешённых в чате
  (`getChat` → `available_reactions`; `None` — разрешены все). Платные реакции ботам недоступны.

## Что сделать

### 1. БД (db.py, `.claude/rules/db.md`)
- `group_messages.tg_message_id INTEGER` — `ALTER TABLE … ADD COLUMN` в списке миграций рядом с `hidden` (NULL для старых строк).
  Индекс `(chat_id, tg_message_id)`.
- `save_group_message(..., tg_message_id: int | None = None)` — заполнять ВЕЗДЕ, где пишется строка: сообщения людей (все ветки:
  текст, фото, документ, голос, кружок, видео, GIF, стикер) и ответы бота во всех ветках (текст/фото/документ/рисование/обзор/
  активность — `message_id` отправленного сообщения; ответ из нескольких частей — id ПЕРВОЙ части). Инвариант «ответы бота в
  `group_messages` во всех ветках» остаётся — пройди все вызовы `save_group_message(..., is_bot=True)` по grep и перечисли в отчёте.
- Новая таблица `message_reactions(chat_id, tg_message_id, user_id, sender_name, emoji, ts)`, `PRIMARY KEY (chat_id,
  tg_message_id, user_id, emoji)`. Свои реакции бот пишет туда же с `user_id = bot id`.
- Функции: `set_user_reactions(chat_id, msg_id, user_id, name, emojis: list[str], ts)` (заменяет набор человека на сообщении —
  так проще, чем считать разницу), `get_reactions_for(chat_id, msg_ids) -> dict[msg_id, list[row]]`.
- Чистка: реакции удаляются вместе со строками `group_messages`, которые режет `GROUP_MESSAGES_KEEP` (тот же запрос/джоба) —
  иначе таблица растёт без предела. Где ещё удаляются строки `group_messages` — найди и почисти реакции там же.

### 2. Чтение: обработчик `message_reaction`
- `MessageReactionHandler` (PTB 22.8) → `on_message_reaction`: только группы; `user` есть (не анонимно); не сам бот; чат
  разрешён (`allowed_chats`, как для обычных сообщений); `user_is_ignored` — не важно, реакции записываем всем.
- Эмодзи — только `ReactionTypeEmoji`; `custom_emoji`/`paid` — пропускать (у модели нет способа их понять).
- Пишем всегда, даже если сообщения нет в `group_messages` (старое) — в запрос такие не попадут, вреда нет.
- Апдейт идёт через `PerChatUpdateProcessor` по ключу чата — проверь, что `message_reaction` получает ключ чата (а не общий):
  ничего не блокирует надолго и не вызывает модель. Модель на реакцию НЕ зовём (иначе каждый 👍 стоит денег).

### 3. Показ модели: `reactions_note` в хвосте
- Строится по строкам ТЕКУЩЕГО окна транскрипта (`build_group_messages` → `info`), только для строк с `tg_message_id` и
  реакциями. Формат, примерно: «Реакции: на твою реплику 10:15 «начало…» — 😁×3 (Аня, Боря, Ник#1234); на «…» Бори 10:20 — 👍
  (ты)». Подписи людей — те же, что в окне (`group_sender_labels`; реагировавшего, которого нет в окне, — по `sender_name`).
  Свои реакции бота — «(ты)», чтобы модель знала, что уже отреагировала.
- Новее — первыми; лимит `REACTIONS_NOTE_MAX_CHARS = 400`, обрезка целыми пунктами. Пусто — строки нет.
- Только `service_block` последнего user-turn (как `participants_note`), НЕ в system и НЕ в строки истории: реакции меняются
  задним числом, правка старых строк ломает кэш префикса (`docs/claude/prompt-cache.md`).
- Где: основной групповой диалог, спонтанная реплика (`_activity_task`), проверка реакций (п. 4). Обзор дня — не трогать.
- В групповой аддендум — одна фраза: «Реакции людей — сигнал, как приняли реплику; не комментируй их без повода».
- Размер: оцени прирост хвоста на живом окне (в отчёте — символы до/после на стенде).

### 4. Свои реакции: `reaction_check`
Отдельная фоновая проверка, независимая от ответа и от `/activity`.
- **Когда** (`reaction_should_check`, дешёвые проверки первыми, без побочных эффектов, как `activity_should_check`):
  группа; есть строка-текст (или описание медиа) от человека; автор не в автоигноре; с прошлой проверки в чате прошло
  `REACTION_RECHECK_MIN = 3` мин (память процесса) И после неё пришло ≥ `REACTION_MIN_NEW = 3` новых строк людей; за сутки бот
  поставил в чате меньше `REACTION_DAILY_CAP = 15` реакций. Тариф — любой (решение «на все»): в free вызов Luna — за счёт бота,
  в отчёте — расход за прогон и оценка на день для самой активной группы прода по числу сообщений.
- **Вызов**: Luna (`DEFAULT_MODEL_ID`), `aux_create`, `label="reaction_check"`, `**aux_params()`, `max_tokens=out_tokens(..., 60)`,
  фоном через `_spawn_background_task`, `usage_ctx` — чат группы. Добавить `reaction_check` в `FALLBACK_QUIET_LABELS`.
- **Вход**: последние `REACTION_TRANSCRIPT_LINES = 10` строк с номерами `[1]…[10]` (НЕ id Telegram — модель их не видит;
  номер → `tg_message_id` держим в коде), подписи как в окне, лимит по размеру (как `ACTIVITY_TRANSCRIPT_CHARS`), строка
  `reactions_note` для этих строк, список разрешённых эмодзи.
- **Промпт** (`_REACTION_SYSTEM`, статичный): поставить реакцию, только если реплика явно смешная/тёплая/впечатляющая/грустная и
  живой участник бы отреагировал; по умолчанию — нет; не на свои реплики; не туда, где уже стоит твоя; характер чата
  (`tone` режима) влияет на выбор эмодзи. Ответ — JSON `{"react": null}` или `{"react": {"n": 7, "emoji": "😁"}}`, разбор —
  `parse_json_lenient`.
- **Проверка ответа в коде**: `n` в диапазоне; строка не бота; у строки есть `tg_message_id`; эмодзи ∈ `REACTION_CHOICES` ∩
  разрешённые в чате; бот ещё не реагировал на это сообщение. Не прошло — в лог, ничего не ставим.
- `REACTION_CHOICES` — константа, ~20 стандартных эмодзи; БЕЗ 👀 и ✍ (это «работаю»). Список — в ТЗ-отчёт, Алексей посмотрит.
- Разрешённые в чате — `getChat().available_reactions`, кэш на чат 1 ч; ошибка — считаем «все».
- **Постановка** — через ту же очередь `_queue_reaction` (порядок поставить/снять). Запись в `message_reactions` с bot id.
- **Конфликт с рабочими реакциями**: на сообщение, где сейчас висит 👀/✍ (`_reacted`), спонтанную не ставим. Если спонтанная уже
  стоит, а потом ставится рабочая — после `unreact` вернуть спонтанную (а не снять всё): `unreact` смотрит в `message_reactions`
  (bot id) и ставит её обратно. Тест на это.
- Отказ Telegram (`REACTION_INVALID`, нет прав, сообщение удалено) — warning в лог, запись в таблицу НЕ делаем.

и, если нет, попроси Алексея.
1. Выкатка ветки на стенд, миграция прошла: `PRAGMA table_info(group_messages)` — колонка есть.
2. `a!:`/`b!:` — несколько реплик; в `group_messages` у новых строк `tg_message_id` заполнен (и у ответа бота на `a:`).
3. `b` ставит 😁 на реплику бота → строка в `message_reactions`; `a:` обращение → в логе/хвосте запроса виден `reactions_note`
   (как проверить хвост — придумай: лог длины или отладочный вывод на стенде, не в проде).
4. `b` снимает реакцию → строка исчезла.
5. Наполнить чат явно смешными репликами (≥ `REACTION_MIN_NEW`) → бот сам ставит реакцию без ответа (`usage_log` label
   `reaction_check`, запись в `message_reactions` с bot id). Несколько раз — проверить, что не на каждую.
6. Кулдаун и дневной лимит — юнит-тестом или временно уменьшенными константами через env на стенде (выбери, укажи).
7. Конфликт с рабочей реакцией: бот поставил спонтанную → на это же сообщение `a:` «найди …» реплаем → 👀 → ответ → вернулась
   спонтанная.
8. В группе с урезанными реакциями (настройка группы — попросить Алексея) бот не ставит запрещённое.
9. `usage_log` за прогон: все вызовы `reaction_check` на чат группы, с меткой; сумма — в отчёт.

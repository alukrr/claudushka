# Чек-лист стенда: `feat/memory-backfill` (`/memory_backfill` — разовая обработка старых личных тредов, v2.14.0)

ТЗ — `docs/claude/tz-private-memory.md` (часть 2), устройство — `docs/claude/memory.md` → «Первичная обработка личных тредов». Места и функции `q` / `logs` — `docs/claude/staging-aliases.sh`.
Новая команда и вызов модели на всех личных тредах → **стенд обязателен**. Часть 1 (каденс) уже на проде (v2.13.1).

Выкатка: в `~/claudushka-test` `git fetch && git checkout --detach origin/feat/memory-backfill`, затем
`docker compose -f docker-compose.test.yml up -d --force-recreate claudushka-test` (новых переменных и volume нет; файл отметок создаётся кодом в `data/`).
**Бэкап БД стенда** перед началом. Нужны: тестовый бот, личка админа с ним; на стенде есть личные треды (копия прод-данных или набранные вручную, ≥ 3 человека).
Прод, dnd и `edge` не трогать. Только тестовый бот. `<UID>` и ники в репозиторий не писать.

## Что можно пройти БЕЗ живого Telegram (делает агент, на копии БД стенда и в контейнере)
| Что | Ожидание |
|---|---|
| Тесты ветки и весь набор (`TELEGRAM_BOT_TOKEN=x ANTHROPIC_API_KEY=x python -m pytest scripts -q`), на Python 3.12 стенда | зелёные (локально 1299 passed, 16 новых в `test_memory_backfill.py`) |
| `ast.parse` + дубли имён | OK и `[]` |
| `dry` на данных стенда: `backfill_plan` | числа людей/реплик/вызовов совпадают с `SELECT user_id, COUNT(*) FROM conversations GROUP BY 1` (тред из <2 строк пропущен) |
| `run` на 2–3 людях (копия БД, живая модель через пул) | строки `usage_log` `label=memory_backfill`, `chat_id` = личный чат админа, модель Lite; личные факты `private`/`NULL`/`long`; предложения профиля `chat_id=0`; отчёты ушли |
| `stop` посреди | остановка после текущего вызова, отметки на месте |
| Рестарт (новый процесс) и продолжение | продолжение с отметок, обработанное заново не вызывается и не оплачивается |

## Шаги в Telegram (только живым) — личка админа с тестовым ботом
| Шаг | Что делаю | Ожидание |
|---|---|---|
| 1 | `/memory_backfill` | Справка и состояние: «не идёт», людей/реплик осталось, обработано людей |
| 2 | `/memory_backfill dry` | «Пробный прогон (ничего не вызывала): людей N, реплик M, вызовов K», оценка времени и расхода. **В `usage_log` новых строк нет**, файла `data-test/memory_backfill.json` нет |
| 3 | В группе / от не-админа `/memory_backfill run` | В группе — «только в личном чате»; не-админу — тишина. Ничего не запустилось |
| 4 | `/memory_backfill run` | «Запускаю обработку…»; следом сообщение «началась: людей в базе N». Бот в это время отвечает в других чатах (написать ему в личке/группе — отвечает без заметных задержек) |
| 5 | Сразу ещё раз `/memory_backfill run` | «Обработка уже идёт — дождись отчёта или stop» |
| 6 | `/memory_backfill stop` через несколько вызовов | «Останавливаю…», затем отчёт «остановлено» с числами; новых вызовов нет |
| 7 | `docker restart claudushka-test`, затем `/memory_backfill`, `/memory_backfill run` | Отметки целы (`q`-проверка файла); `run` продолжает; уже обработанные люди не обрабатываются заново (в `usage_log` нет повторных кусков) |
| 8 | Дождаться конца (или `stop`) | Итоговый отчёт: люди/куски/факты/предложения/ошибки/расход |
| 9 | `q "SELECT chat_id,label,model,billed,COUNT(*),SUM(cost_usd) FROM usage_log WHERE label='memory_backfill' GROUP BY 1,2,3,4"` | Одна строка-группа: `chat_id` = id админа (не пользователей), Lite |
| 10 | `q "SELECT user_id,COUNT(*) FROM memory WHERE context='private' GROUP BY 1"` и `/memory` у тестового человека | Личные факты появились у обработанных; у необработанных (после `stop`) — нет |
| 11 | `/profile` (админ) | Ожидающие предложения профиля из обработки (если `run` без `facts`) |
| 12 | dedup TUI на копии базы | Узел «личка» показывает личные факты |
| 13 | `logs 300 \| grep -iE "Traceback\|memory_backfill"` | Нет Traceback; строки ошибок кусков — только если ошибки модели были |

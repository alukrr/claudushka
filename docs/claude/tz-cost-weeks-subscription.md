# ТЗ: недели в расходах и оценка цены подписки (`feat/cost-weeks-subscription`)

Постановка Алексея 2026-11-10, после просмотра экрана «Расходы» (v2.8.0) на живых больших чатах. Продолжение `feat/miniapp-v2`
(`docs/claude/tz-miniapp-v2.md`, `docs/claude/miniapp.md`): данные — тот же `_cost_data`, права — те же. **Схему БД не меняем.**
Сама подписка (оплата, списание, тариф «подписка») — НЕ в этой задаче: здесь только ОЦЕНКА цены, чтобы решить, сколько брать.

## Решения Алексея (2026-11-10)
- Недели — по немецким правилам (DIN 1355 / ISO 8601): начало в понедельник, KW 1 — неделя с первым четвергом года. 12 последних, текущая —
  «по сегодня».
- Цена подписки: окно **90 дней, но не раньше 2026-10-28** (с этой даты модели — только Gemini, траты на Claude не репрезентативны).
- **Месяц = 30 дней.** Неделя = 7 дней **+5%**.
- Платных дней в окне **меньше 7** → цену не показываем, пишем «мало данных: N дн. в платном режиме».
- Цену видят **все, кто видит расходы**: экран «Расходы» (админы чата, управляющие, админ бота), `/cost` в группе, `/cost <chat_id>`.

## Часть 1. Недели
- `_cost_week_windows(now, count=12)` рядом с `_cost_month_windows`: границы — понедельник 00:00 `BERLIN_TZ` (через `datetime.combine`, не `+7 дней`
  к timestamp — DST), номер — `date.isocalendar()` (год ISO может отличаться от календарного: 29.12.2025 — KW 1 2026; в подписи год ISO).
- В `_cost_data`: `weeks: [{week: "2026-W46", kw: 46, iso_year: 2026, start: "2026-11-09", end: "2026-11-15", partial, paid, free?}]`, новые сверху,
  `free` — только при `show_free` (как у месяцев).
- `/cost <chat_id>`: блок «По неделям (платное / бесплатное)» между «По дням» и «По месяцам», строка `KW 46 (09.11–15.11): $x / $y (по сегодня)`.
- Экран «Расходы»: блок «По неделям» той же формы, что «По месяцам» (таблица + полоски).

## Часть 2. Оценка цены подписки
### Дни в платном режиме — по восстановленному балансу, НЕ по «дням с тратами»
Тариф хранится не таблицей, а вычисляется: `chat_tier` = `paid`, если баланс > `db.PAID_MIN_BALANCE` (личка админа бота — всегда `paid`).
Баланс в любой момент восстанавливается из двух журналов с `ts`: `chat_credits` (`topup`, `bonus`, `writeoff` и прочие `kind` — все с `amount`) и
`usage_log` с `billed=1` (минус `cost_usd`). Алгоритм (`_paid_seconds(chat_id, since_ts, until_ts) -> float`, чистая функция над списком событий
для тестов + обёртка, читающая БД):
1. Баланс на `since_ts` = сумма всех событий до него. Затем события в окне по `ts` (при равном `ts` — сначала кредиты, потом траты).
2. Интервал между соседними событиями — платный, если баланс на его начале > `PAID_MIN_BALANCE`. Сумма длин платных интервалов, конец — `until_ts`.
3. Личка админа бота (`is_admin(chat_id)`) — всё окно платное.
Считать «дни с платными тратами» НЕЛЬЗЯ: тихий день в платном режиме выпадет из знаменателя, цена завысится. Подтверждение корректности:
`billed=1` пишется только в платном режиме (`_record_usage`), значит каждая строка `billed=1` должна попадать в восстановленный платный интервал —
это проверка в тестах и при сверке на прод-данных.
Новые функции чтения в `db.py` (без изменения схемы): события `chat_credits` и `usage_log billed=1` по чату до `until_ts` — суммой до `since_ts`
одним запросом и списком внутри окна. Посмотреть `db.get_balance`: восстановленный баланс на `now` обязан совпасть с ним (тест).

### Формула
- Окно: `start = max(now − 90 дней, 2026-10-28 00:00 Berlin)` (константа `SUBSCRIPTION_EST_SINCE`), `end = now`; `SUBSCRIPTION_EST_DAYS = 90`.
- `paid_days = _paid_seconds(...) / 86400`; `spent = Σ cost_usd billed=1` за окно.
- `paid_days < SUBSCRIPTION_MIN_DAYS` (7) → `{"enough": false, "paid_days": …}`.
- Иначе `per_day = spent / paid_days`; **месяц** = `per_day × 30` (`SUBSCRIPTION_MONTH_DAYS`); **неделя** = `per_day × 7 × 1.05`
  (`SUBSCRIPTION_WEEK_MARKUP = 0.05`). Деньги в `usage_log.cost_usd` уже с `PRICE_MARKUP` — второй раз не умножать.
- В `_cost_data`: `subscription: {enough, month, week, paid_days, spent, window_days, since}`. Бесплатное в оценку не входит никогда,
  поэтому показывать можно всем, кто видит расходы.
- Константы — в bot.py рядом с прочими ценами, в одном месте.

### Где показать (сверху)
- Экран «Расходы»: под шапкой с балансом — «В режиме подписки: месяц ≈ $X, неделя ≈ $Y» и мелко «по N дн. платного режима с DD.MM». При
  `enough=false` — «Цена подписки: мало данных (N дн. в платном режиме, нужно 7)».
- `/cost` в группе (`_cost_report` со `scope=chat_id`) и `/cost <chat_id>` (`_cost_detail`) — та же строка второй строкой ответа. Личка
  пользователя (`scope=user_id`) — тоже (это его «чат»). Общий `/cost` админа (все чаты) — не трогаем.
- Слово «≈» обязательно: это оценка по прошлому, не тариф.

## Не делаем
- Саму подписку, оплату, новый тариф, изменение `chat_tier` — отдельная задача после того, как Алексей посмотрит на цифры.
- Изменение схемы БД, новые таблицы (истории тарифа нет и не заводим — восстанавливаем из журналов).

## Проверки
- Юнит-тесты `_paid_seconds` на синтетике: пополнение → траты до нуля (переход в free) → тишина → снова пополнение; writeoff; бонус;
  события с одинаковым `ts`; личка админа; окно начинается посреди платного интервала. Каждая `billed=1` — внутри платного интервала.
- Тест: восстановленный баланс на `now` = `db.get_balance`.
- Тест формулы: 15 платных дней из 30 в окне, траты $10 → месяц $20.00, неделя $4.90 (10/15×7×1.05).
- Тест недель: ISO-год на стыке (29.12.2025 → 2026-W01, 31.12.2024 → 2025-W01), DST-неделя, `partial`, `show_free=False` → нет `free`.
- `ast.parse` + проверка дублей имён верхнего уровня (DoD п. 4).
- **Сверка на прод-данных, только чтение:** копия прод-БД через `sqlite3.backup` (как в `docs/claude/staging.md`, раздел «Бэкап») в `/tmp`
  на сервере, скрипт считает для 5 крупнейших чатов недели, `paid_days`, цену, и проверяет «каждая billed=1 внутри платного интервала» и «баланс
  на now = get_balance». Результат — Алексею в отчёт. Боевую БД не писать; копию удалить после.
- Стенд — по желанию Алексея (`/cost` и экран «Расходы» уже проверены в v2.8.0; меняется только наполнение). По правилу CLAUDE.md
  «мелкий фикс vs стенд» это НЕ мелкий фикс (новая логика), поэтому по умолчанию — стенд, решение за Алексеем.

# ТЗ: рисование — дословно только по кавычкам и `/imagine` (`feat/draw-intent`)

Постановка Алексея 2026-11-01 (п.4 `docs/claude/roadmap-2026-11.md`). ТЗ написано для отдельной сессии исполнителя;
исполнитель **сначала читает `CLAUDE.md` целиком** (особенно «Definition of Done» и «Инварианты») и
`docs/claude/images.md`, раздел «Рисование: два пути входа».

## Проблема
Сейчас любое сообщение, где первое слово из `DRAW_TRIGGERS` (bot.py, рядом с `BOT_TRIGGERS`), идёт мимо диалоговой
модели: весь хвост после триггера уходит в генератор картинок как промпт (ветка `# Check for draw request` в
`handle_message`, затем `_draw_and_send` с переводом через Lite). Получается ерунда:
- «нарисуй что происходит в чате» → провайдер получает промпт «что происходит в чате» и рисует абстракцию;
- «а нарисуй что происходит в чате» работает хорошо: первое слово «а», сообщение уходит в диалог, модель видит
  контекст, сама пишет промпт и ставит маркер `[[DRAW: ...]]`;
- «покажи курс евро» → тоже генератор картинок, потому что «покажи» входит в `DRAW_TRIGGERS`.

## Что должно стать
| Сообщение (в группе — после обращения к боту, `strip_trigger`) | Поведение |
|---|---|
| `/imagine <текст>`, `/imagine 2k <текст>` | **без изменений** (дословно, как сейчас) |
| `нарисуй "кот в шляпе"`, `нарисуй «кот в шляпе»`, `нарисуй 2к “кот”` | **дословно**: текст в кавычках → текущий путь `_draw_and_send` (с переводом через Lite, как сейчас) |
| `нарисуй кота в шляпе`, `нарисуй что происходит в чате`, `нарисуй` + reply на сообщение | **через диалог**: модель сама пишет промпт и ставит `[[DRAW: ...]]`; служебный блок говорит ей, что картинку явно просят |
| `а нарисуй …`, `Клодушка, ну нарисуй …` (триггер не первым словом, но среди первых 3 слов) | через диалог, тоже с пометкой «явно просят картинку» |
| `покажи …` | обычный диалог (без пометки), «покажи» больше не триггер |
| `нарисуй ""` / `нарисуй` без текста и без reply | как сейчас: «Что нарисовать? …» |

### Детали
1. **Чистая функция разбора** (новая, рядом с `DRAW_TRIGGERS`):
   `parse_draw_request(text: str) -> tuple[str | None, str, str | None]` → `(mode, prompt, size)`:
   - `mode = "literal"` — первое слово из `DRAW_TRIGGERS`, после него (и после необязательного `2к`/`2k` из
     `IMAGE_2K_WORDS`) сразу идёт открывающая кавычка. `prompt` — содержимое между первой открывающей и последней
     закрывающей кавычкой; хвост после последней закрывающей, если он есть, добавить через пробел. Кавычки:
     открывающие `" « „ “ ' ‘`, закрывающие `" » “ ” ' ’` (iOS/Android сами заменяют `"` на `“”` или `«»`). Если
     закрывающей нет — всё до конца строки.
   - `mode = "intent"` — первое слово из `DRAW_TRIGGERS` без кавычек ИЛИ триггер среди первых 3 слов
     (сравнение как сейчас: `lower().rstrip(",:.!?")`). `prompt` — исходный текст целиком (он уйдёт в диалог как
     обычная реплика). `size = "2K"`, если сразу после триггера стоит `2к`/`2k`.
   - `mode = None` — не про рисование.
   - Пустой `prompt` в `literal` → вернуть `("literal", "", size)`, вызывающее место ответит «Что нарисовать?».
2. **`DRAW_TRIGGERS`**: убрать `"покажи"`. Остаются `нарисуй`, `нарисуй-ка`, `рисуй`, `изобрази`, `draw`, `zeichne`.
3. **Ветка `literal`** в `handle_message` — нынешний код ветки `# Check for draw request` почти без изменений
   (сохранение пары в `conversations` в личке, `_count_reply`, `author`). Разница одна: reply-подхват
   (`if not draw_prompt and update.message.reply_to_message`) из этой ветки **убрать** — `нарисуй` + reply без
   кавычек теперь `intent`, модель увидит цитату через `reply_context`.
4. **Ветка `intent`** — НЕ делает `return`, идёт в обычный диалог (`# Main conversation`), но:
   - **до** вызова модели проверить лимит free: `await _image_limit_blocked(update, chat_id, is_group, user_id)`
     (не silent). Исчерпан → ответ о лимите уже отправлен функцией, `return`, модель не вызываем, в
     `conversations` ничего не пишем (как `/imagine`). В группе реплика человека уже сохранена пассивным блоком —
     это нормально.
   - в `service_block` (bot.py, «Изменчивый контекст запроса…») — новый keyword-аргумент `draw_intent: bool = False`
     и `draw_size: str | None = None`. При `draw_intent=True` добавить строку примерно такого смысла: «Пользователь
     явно просит нарисовать картинку. Придумай промпт сам — по смыслу просьбы, контексту чата и цитате, если есть, —
     не переводи его просьбу дословно. Обязательно добавь маркер [[DRAW: …]] (при draw_size == "2K" —
     [[DRAW 2K: …]]). Отказаться можно только по правилам безопасности». Пробросить через `compose(...)` — тогда
     повтор без истории после safety-блока (`_dialog_call`, `retry_messages=lambda: compose(...)`) получит ту же
     пометку. **System не трогать** (инвариант prompt cache: изменчивое — только в служебном блоке).
   - при обработке маркера (`if draw_en_prompt: await _draw_and_send(...)` в конце диалога) передавать
     `silent_limit=not draw_intent` и `author=<имя автора>` при `draw_intent` (подпись «Автор запроса» как у явного
     пути). Лимит уже проверен выше, но между проверкой и рисованием мог уйти параллельный запрос — пусть
     `_draw_and_send` проверит ещё раз и при `draw_intent` скажет об этом вслух.
   - если `draw_intent=True`, а модель маркер не поставила (и `LEAKED_*`-подстраховка не сработала) —
     `logger.warning(f"draw_intent без маркера chat=… uid=…")`, текст ответа отдать как есть. Не рисовать по
     исходному тексту молча — именно этого Алексей просил избежать.
5. `/imagine`, маркер `[[DRAW]]` в обычных ответах, `LEAKED_DRAW_*`, `_draw_sent_note`, провайдеры, цены — **не трогать**.

стенд не гоняет (нет доступа), только пишет чек-лист; гоняет Алексей.

## Контекст и деньги (оценить в отчёте)
- `intent` теперь стоит один диалоговый вызов модели чата + картинка (раньше — Lite-перевод + картинка). На Flash это
  дороже на цену одного ответа; при `literal` — без изменений.
- Служебный блок +1 строка (~300 символов) только в сообщениях с `intent`; system не меняется, кэш не ломается.

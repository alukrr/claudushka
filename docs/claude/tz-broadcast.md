# ТЗ: рассылка о нововведениях по активным чатам (`feat/broadcast`)

Постановка Алексея 2026-11-10 (правка П2 к `tz-stars-topup.md`, вынесена отдельно). Нужно сообщать всем активным чатам и личкам о новом
(например, о пополнении звёздами). Решение Алексея: запуск **из лички с ботом**, админом бота; должна быть возможность отправить **стикер**.

## Как работает
1. Админ бота в личке пишет обычное сообщение (текст с форматированием, стикер, фото/видео с подписью) и отвечает на него командой
   **`/broadcast`**. Вариант `/broadcast test` — отправить только админам бота (проверить, как выглядит).
2. Бот отвечает предпросмотром: «Уйдёт в N групп и M личек» + кнопки «Отправить» / «Отмена». Без нажатия ничего не уходит; кнопка работает
   только у того, кто запустил, и только один раз.
3. Отправка — фоновой задачей (`_spawn_background_task`), копированием исходного сообщения (метод Bot API `copyMessage`: получатель не видит
   «переслано от»; стикеры и медиа копируются как есть — **сверить по core.telegram.org/bots/api, что стикер копируется; если нет — отправлять
   стикер по `file_id`**). Несколько сообщений подряд (стикер + текст) = два запуска `/broadcast`.
4. По завершении — отчёт запустившему: отправлено / бот заблокирован или удалён из чата / ошибки, длительность.

## Кому («активные»)
- **Группы:** есть в `allowed_chats`, не забанены, в `group_messages` есть сообщение человека за последние `BROADCAST_ACTIVE_DAYS` (30) дней.
- **Лички:** `users` не забанен, `last_active` за те же 30 дней, человек писал боту в личке (есть строки в `conversations`).
- Админы бота получают всегда. Чат в автоигноре/на паузе — получает (это объявление, а не ответ).
- Число дней — переменная; `/broadcast all` — всем известным незабаненным, без фильтра активности (показать число в предпросмотре).

## Ограничения и надёжность
- Темп: не быстрее `BROADCAST_RATE_PER_SEC` (по умолчанию 20) сообщений в секунду — лимиты массовой рассылки **сверить по
  core.telegram.org/bots/faq**; на ответ «слишком много запросов» (`RetryAfter`) — ждать указанное время и продолжать.
- «Бот заблокирован» / «бота нет в чате» — не ошибка, считается в отчёте, рассылка идёт дальше.
- Повтор без дублей: маленькая новая таблица `broadcast_log(broadcast_id, chat_id, status, ts)` — при рестарте бота посреди рассылки
  `/broadcast resume` дошлёт только тем, кому не ушло. (Новая таблица → схема меняется, обратно совместимо. Если Алексей против таблицы —
  состояние только в памяти, и рестарт посреди рассылки = «кому-то не дошло», в отчёте это не увидеть.)
- Одна рассылка одновременно. `/broadcast stop` останавливает.
- Копии в группах **не** пишутся в `group_messages` как реплика бота? — писать (`is_bot=True`, инвариант «бот видит свои реплики»), с пометкой
  служебного объявления, чтобы модель не принимала его за ответ на чьё-то сообщение; для стикера — плейсхолдер.
- Деньги: рассылка не вызывает моделей, в `usage_log` ничего не пишет.

## Не делаем
Отписку от объявлений по чатам, расписание, сегменты (только платные и т. п.), запуск из мини-приложения.

## Проверки
Юнит-тесты: отбор получателей (активность, бан, админы), подтверждение только автором и один раз, `RetryAfter`, «заблокирован» не роняет
рассылку, `resume` не дублирует. Стенд: `/broadcast test`, затем настоящая рассылка по тестовым чатам — текст, стикер, фото.
`ast.parse`, дубли имён (DoD п. 4).

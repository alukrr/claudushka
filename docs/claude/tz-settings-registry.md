# ТЗ: единый реестр настроек чата (`feat/settings-registry`)

Подготовка к мини-приложению (`docs/claude/tz-miniapp.md`, п.1 `docs/claude/roadmap-2026-11.md`). Сейчас права на каждую
настройку зашиты в свою команду, и правила у них разные. Мини-приложение должно применять ровно те же правила — поэтому
сначала выносим их в одно место, а команды переводим на него **без изменения поведения**. Это рефакторинг: пользователь
ничего не должен заметить.

ТЗ для отдельной сессии исполнителя: **сначала прочитать `CLAUDE.md` целиком**, затем `docs/claude/models-and-costs.md`,
`docs/claude/images.md` (провайдеры, restricted), `docs/claude/personas.md`, `docs/claude/daily-review.md` (вкл/выкл),
`docs/claude/native-search.md` (`/searchmode`), `docs/claude/group-chat.md` (активность, автоигнор), `docs/claude/billing.md` (тарифы).

## Шаг 1 — характеризационные тесты ДО рефакторинга
Новый `scripts/test_settings_registry.py`. Сначала, на нетронутом коде, — таблица «кто / какой чат / тариф / значение →
разрешено или какой отказ» для команд из списка ниже, через вызов самих хендлеров с подменённым `update`/`context`
(образец подмен — `scripts/test_review_persona.py`, `scripts/test_group_behavior.py`). Закоммитить отдельно (`test:`), убедиться,
что зелёные. После рефакторинга те же тесты должны пройти без правок ожиданий — это и есть доказательство «поведение не
изменилось». Если какой-то тест пришлось поменять — это изменение поведения, остановиться и спросить Алексея.

## Текущие правила (сверить с кодом — источник правды код, не этот список)
| Ключ | Где | Сейчас | Кто меняет | Free | Особое |
|---|---|---|---|---|---|
| `model` | личка, группа | `_set_chat_model`, `chat_models` | любой участник; `restricted` в группе — админ чата/бота (`_deny_restricted`) | не админ бота — отказ (Lite — «и так Lite»); админ бота — запись с пометкой | проба модели перед записью (кроме Lite) |
| `image_provider` | личка, группа | `_set_image_provider` | как `model` (`bananapro` restricted) | как `model` | без пробы |
| `persona` | личка, группа | `_set_persona` | личка — сам; группа — админ чата/бота | не админ бота — отказ с режимом дня | — |
| `review_persona` | группа | `cmd_review_persona` | смотреть все; менять админ чата/бота | не админ бота — отказ | `off` = удалить строку |
| `review_enabled` | группа | `_set_chat_review_enabled` | админ чата/бота | без тарифной проверки | нет строки чата — отказ |
| `search_mode` | личка, группа | `cmd_searchmode` | любой | не админ бота — отказ | — |
| `activity` | группа | `cmd_activity` | смотреть все; менять админ чата/бота | сохраняется, но не работает (пометка) | 0–100 |
| `autoignore` | группа | `cmd_autoignore` | админ чата/бота (и смотреть) | без тарифной проверки | — |
Чужой чат (`chat_id` аргументом) — во всех командах только админ бота.

## Шаг 2 — реестр (в `bot.py`, отдельной секцией; НЕ новый файл — новый `.py` требует правки compose)
- `@dataclass(frozen=True) class ChatSetting`: `key`, `label` (по-русски), `scope` (`"group" | "both"`), `kind`
  (`"choice" | "int" | "bool"`), `choices: Callable[[int], list[tuple[str, str]]] | None` (значение, подпись — из реестров
  `MODELS`, `IMAGE_PROVIDERS`, `PERSONAS`, `SEARCH_MODES`, без хардкода), `int_range: tuple[int, int] | None`,
  `get: Callable[[int], dict]` → `{"value": действующее, "stored": сохранённое или None, "note": пояснение или ""}`
  (например, free: «бесплатный режим — всегда Lite», «режим дня»),
  `who: Literal["anyone", "chat_admin"]`, `restricted_values: Callable[[], set[str]]` (значения, которые в группе меняет только
  админ чата/бота), `free_policy: Literal["deny", "admin_saves", "allow"]`, `apply: Callable` — async-запись с побочными
  эффектами (проба модели для `model`; удаление строки для `review_persona=off`).
- `SETTINGS: dict[str, ChatSetting]` — восемь ключей из таблицы.
- Политика — ОДНА чистая функция без Telegram:
  `can_change(key, *, actor_id, is_bot_admin, is_chat_admin, target_chat_id, in_target_chat, tier, value) -> tuple[bool, str]`
  (`str` — причина отказа, тексты как у команд сейчас). `is_chat_admin` считает вызывающий (это async-запрос к Telegram) и передаёт
  флагом. Порядок проверок должен давать те же отказы, что команды сейчас (это проверяют тесты шага 1).
- `async def apply_setting(key, chat_id, value, *, context, probe_chat_id) -> tuple[bool, str]` — валидация значения
  (`choices`/`int_range`), затем `apply`; для `model` — `_probe_model` как сейчас (провал пробы → `(False, текст)`, ничего не пишем).
- Команды из таблицы переписать так, чтобы права и запись шли через `can_change` / `apply_setting`, а тексты ответов, разбор
  аргументов и предупреждения («такого чата нет среди разрешённых», «чат в бесплатном режиме: выбор сохранён…») остались
  прежними. Информационные команды (`/models`, `/imagemodels`, `/personas`, без аргументов) — не трогать, кроме чтения через `get`,
  если это упрощает код без изменения текста.

## Не делать
- Мини-приложение, веб-сервер, compose — это следующая ветка.
- Не менять ни одного правила, текста отказа, дефолта или тарифной логики. `/ratelimit`, `/unignore`, деньги и баны — не в реестре.
- Не мержить, не ставить тег, не заходить на сервер.

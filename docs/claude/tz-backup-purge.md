# ТЗ: автоудаление старых копий базы (`feat/backup-purge`)

Постановка Алексея 2026-11-12. Копии базы на проде никто не удаляет: на момент просмотра их 61 по ~30 МБ (около 1,8 ГБ) —
`data/claudushka.db.bak-*` (ручные, перед деплоями) и `data/backups/*.db` (дедуп, восстановление; дедуп создаёт копию на каждое
применение, до 20 за вечер).

ТЗ для отдельной сессии: **сначала `CLAUDE.md` целиком**, затем раздел «Бэкап» в `docs/claude/staging.md`,
`docs/claude/memory.md` (как устроен `memory_purge_job`), `docs/claude/api-errors.md`.

## Решения Алексея
1. **Джоб внутри бота**, не крон на сервере: в git, под тестами, без правок на сервере (контейнер работает от root и удалить файлы может).
2. **Правило:** удалять копии **старше 14 дней**, но **три самые свежие не трогать никогда**, сколько бы им ни было.
3. Копии перед мажорными версиями (`pre-v2.0.0` и подобные) — на общих основаниях.

## Что сделать
1. **`purge_old_db_backups(now=None, dry_run=False) -> dict`** в `bot.py` (рядом с `purge_forget_backups`):
   - кандидаты — только обычные файлы (не каталоги, не симлинки) по двум шаблонам: `DATA_DIR / "backups" / "*.db"` и
     `DATA_DIR / "claudushka.db.bak-*"`. Больше ничего: ни сама `claudushka.db`, ни её `-wal`/`-shm`, ни `data/forget-backups/`
     (у них своё правило), ни `data/dedup_runs/`, ни `deleted-*.json`;
   - сортировка всех кандидатов вместе по времени изменения, новые первыми; первые `DB_BACKUP_KEEP_NEWEST = 3` пропускаются всегда;
     из остальных удаляются те, что старше `DB_BACKUP_KEEP_DAYS = 14` суток;
   - вместе с копией удалять её спутники `<имя>-wal` и `<имя>-shm`, если есть;
   - ошибка на одном файле — warning в лог и дальше, остальные файлы не страдают;
   - возвращает `{"deleted": [имена], "kept": n, "freed_bytes": n}`; при `dry_run=True` ничего не удаляет, список тот же.
2. **Вызов** — третьим отдельным `try` в `memory_purge_job` (04:30 Berlin и разово на старте), через `asyncio.to_thread`.
   В лог — одна строка: сколько удалено, сколько освобождено, сколько осталось; имена удалённых — отдельной строкой.
3. **Первый запуск на проде.** До выкатки показать Алексею список, который будет удалён: только чтение на сервере (с его «да»),
   той же логикой с `dry_run`. Ориентир на 2026-11-12: старше 14 дней — 32 копии; с 2026-11-14 к ним добавится 21 копия дедупа от 2026-10-30.
4. Имя джоба и расписание не менять. Новых переменных окружения и команд не заводить.

## Не делать
- Не удалять ничего вне двух шаблонов. Не трогать `data-test` стенда руками (там работает тот же джоб тестового бота на своём каталоге).
- Не менять `backup_db` в `dedup_memory.py` и команду бэкапа в `docs/claude/staging.md`, кроме приписки из раздела «Документация».
- Не мержить, не ставить тег, на сервер — только с «да» Алексея, удаление руками на сервере не делать.

## Тесты
`scripts/test_backup_purge.py`, временный каталог, время файлов — `os.utime`: старые удаляются, свежие остаются; три самые свежие
остаются, даже если всем по году; меньше трёх копий — не удаляется ничего; граница ровно 14 суток; оба шаблона считаются вместе;
`claudushka.db`, её `-wal`/`-shm`, чужие файлы и `forget-backups/` не тронуты; спутники удаляются вместе с копией; симлинк и
каталог с подходящим именем не тронуты; ошибка удаления одного файла не мешает остальным; `dry_run` ничего не удаляет; каталога
`backups/` нет — не ошибка. Остальные `scripts/test_*.py` зелёные.

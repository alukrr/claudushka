# Чек-лист стенда: ТЗ `feat/chat-managers` (управляющие чата, v2.5.0)

ТЗ — `docs/claude/tz-chat-managers.md`, дизайн — `docs/claude/group-chat.md` («Управляющие чата»). Места **TG-админ / TG-участник / Сервер**
и функции `q` / `logs` — `docs/claude/staging-aliases.sh`. Новая таблица `chat_managers` создаётся при старте (`init_db`), новых файлов и volume нет — выкатка
`git pull` + `docker restart claudushka-test`. Юнит-тесты: `python -m pytest scripts/test_chat_managers.py scripts/test_settings_registry.py -q`.
Нужны: тестовая группа стенда в платном режиме (`/topup`), ТРИ аккаунта — **А** (админ чата в Telegram), **В** (обычный участник, не админ),
**С** (второй обычный участник), и аккаунт админа бота (если он не А).

| Шаг | Где | Что делаю | Ожидание |
|---|---|---|---|
| 1 | Сервер | `q "SELECT sql FROM sqlite_master WHERE name='chat_managers'"` | Таблица есть: `chat_id, user_id, added_by, added_at`, PK `(chat_id, user_id)` |
| 2 | Группа, В | `/managers`, `/manager add` (ответом на сообщение С), `/activity 20`, `/review_on` | Все отказы: «только для админов…», «Назначать и снимать управляющих могут только админы…», «Менять активность могут…», «…может только админ этого чата» |
| 3 | Личка, А | `/manager add 5`, `/managers` | «/manager работает только в групповых чатах», «/managers работает только в групповых чатах» |
| 4 | Группа, А | `/manager add` ответом на сообщение В | «{Имя В} теперь управляет ботом в этом чате (как админ чата).»; `q "SELECT * FROM chat_managers"` — строка с `added_by` = uid А |
| 5 | Группа, А | `/manager add` ответом на своё сообщение; на сообщение админа бота; `/manager add <uid бота>` или ответом на сообщение бота | «{Имя} и так админ.» (дважды); «Бота управляющим сделать нельзя.»; в таблице новых строк нет |
| 6 | Группа, А | `/manager add abc`, `/manager add 1` (uid не из этого чата), `/manager`, `/manager zzz` | «user_id — число…»; «Не нашла такого участника в этом чате…»; два раза «Формат: /manager add\|rm…»; строк не прибавилось |
| 7 | Группа, В (теперь управляющий) | `/managers` | Список: имя В, его uid, кто добавил (А) и время по Берлину |
| 8 | Группа, В | `/activity 20`, затем `/activity` | Значение сохранено (20); `q "SELECT activity_percent FROM allowed_chats WHERE chat_id=<id>"` = 20 |
| 9 | Группа, В | `/review_on`, `/review_persona toxic`, `/autoignore`, `/ratelimit` (ответом на сообщение С: `/ratelimit 1`) | Проходят как у админа чата (обзор включён, характер обзора записан, состояние автоигнора, лимит выставлен); `q "SELECT daily_review_enabled FROM allowed_chats WHERE chat_id=<id>"` = 1 |
| 10 | Группа, В | `/classic` (характер чата), `/bananapro` (restricted-картинки) | Проходят (как админу чата) |
| 11 | Группа, В | `/manager add` ответом на сообщение С; `/manager rm` на себя | Отказ «Назначать и снимать управляющих могут только админы…»; строки не изменились |
| 12 | Группа, В | То, что должно остаться только админу бота: `/topup`, `/ban`, `/update`, `/hidden`, `/activity 20 <чужой chat_id>` | Молчание / отказ «только админ…» — админки бота у управляющего нет |
| 13 | Группа, В | `/cost` | Показывает расход ЭТОГО чата (как админу чата; в ТЗ спорная точка — см. отчёт) |
| 14 | Группа, А | `/manager rm` ответом на сообщение В | «{Имя В} больше не управляет ботом в этом чате.»; строка исчезла |
| 15 | Группа, В | `/activity 50`, `/review_off`, `/managers` | Все отказы; `activity_percent` остался 20, `daily_review_enabled` остался 1 |
| 16 | Группа, А | Снова `/manager add` на В; В выходит из группы (или А исключает его), затем В возвращается | Пока В вне группы — его права не действуют (`left`/`kicked`), `q "SELECT * FROM chat_managers"` — строка остаётся; после возвращения `/activity 30` у В снова проходит без повторной выдачи |
| 17 | Группа, админ бота | `/manager add <uid С>` (по ID), затем `/managers` | Добавлен; «добавил(а)» — имя админа бота; `/manager rm <uid С>` убирает; повторный `rm` — «и так не управляет» |
| 18 | Другая группа стенда | В (управляющий в первой группе) пытается `/activity 20` | Отказ: права только в том чате, где выданы |
| 19 | Группа, В | Три одинаковых обращения к боту (автоигнор) | Управляющий НЕ освобождён от автоигнора (как обычный участник): предупреждение/пауза; освобождены только админы бота |
| 20 | Сервер | `logs 200 \| grep -iE "Traceback\|manager"` | Без Traceback; `usage_log` новых строк от команд нет (команды без LLM) |
